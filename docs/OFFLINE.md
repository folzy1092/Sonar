# Офлайн-режим — техническое задание (ПК и iPhone)

Заказ владельца 2026-11-23. Статус: **сделано 2026-11-23** — этапы 0–5 на ПК, 0–4 и часть 5 на iPhone (таблица раздела 12); iPhone проверен только CI, не на устройстве. Все факты про текущий код сверены с репо на
2026-11-23 (файлы названы ниже); чего не смогли проверить без устройства — в разделе 14.

## 0. Суть в шести строках

1. В **Система → Общее** (ключ `general.offline`) — переключатель «Офлайн-режим». Включён — Sonar **не делает ни одного
   запроса в интернет** (роуминг, слабая сеть, каждый килобайт на счету).
2. Играть можно только то, что уже лежит на устройстве: **скачанное и кэшированное** (обе платформы) и
   **локальные файлы** (сейчас только ПК). Всё остальное **не показывается** — не серое, а скрыто.
3. Режим — **жёсткий и вручную**: «нет сети» и «сеть дорогая» — разные вещи. Автоматически его не включаем
   (максимум — предложение, этап 4).
4. Настройка **не синхронизируется** между устройствами (у телефона роуминг, у ПК дома Wi-Fi) и **переживает перезапуск**.
5. Настройка **ищется в поиске по настройкам** (ПК: `lib/settings-catalog.ts`, синонимы: «офлайн», «оффлайн», «без сети»,
   «роуминг», «трафик», «экономия», «offline»).
6. Главная проблема не в переключателе, а в том, **что есть что показывать**: на ПК нет кнопки «Скачать», автокэш
   выключен по умолчанию; на iPhone не скачивается большинство SoundCloud (HLS). Без этого режим включится в пустоту (раздел 3, 8).

## 1. Сценарии

| Сценарий | Что нужно от режима |
|---|---|
| Выезд в роуминг: интернет есть, но дорогой | Ноль трафика от Sonar, играет то, что скачано дома на Wi-Fi |
| Метро, самолёт, дача — сети нет или рвётся | Чистый интерфейс без вечных спиннеров и красных ошибок |
| Лимит тарифа в конце месяца | Тот же режим вручную |

Для масштаба (чтобы не спорить, зачем это): поток 320 кбит/с — **~144 МБ в час**, 128 кбит/с — ~58 МБ в час. Один трек
в mp3 320 — **~8 МБ**, FLAC — **25–40 МБ** (в коде `track_cache.rs`: «FLAC бывает за 40 МБ»). 100 треков ≈ 0,8 ГБ,
500 ≈ 4 ГБ. Это ориентиры для окна «Скачать» (раздел 8.3), не обещания.

## 2. Термины (одни и те же на ПК и iPhone)

- **Офлайн-режим** — настройка `general.offline`.
- **Доступно офлайн** (`available offline`) — у трека на устройстве есть файл, который сыграет без сети.
  Источники — таблица ниже.
- **Скачанное** — то, что пользователь скачал **сам** («Скачать»). Не вытесняется, пока пользователь не удалил.
  На iPhone уже есть (`DownloadStore`, «Скачанные»), на ПК — **нет, добавляем**.
- **Кэш** — то, что осело само: прослушанное на ПК (`storage.cache_tracks`), подкачанная волна (`storage.wave_offline`).
  Вытесняется по давности. В офлайне оно тоже «доступно», но **не гарантировано**.
- **Локальные файлы** — `local:<sha1 пути>` из «Папок с музыкой» (только ПК).

| Источник | ПК | iPhone |
|---|---|---|
| Скачанное | **новое** (этап 2, ПК) | есть: `DownloadStore`, `Application Support/Sonar/Downloads` |
| Кэш | есть: `track_cache.rs`, папка `<кэш>/tracks`, по умолчанию выкл., 2 ГБ, вытеснение по давности | только волна: `WaveCache`, `Caches/Sonar/WaveCache`, iOS может почистить сама |
| Локальные файлы | есть: `local/`, таблица `local_files` | **нет** (вопрос 1 в разделе 15) |

## 3. Что уже есть и где дыры

**ПК (`windows/src-tauri/src/`):**
- `track_cache.rs` складывает **байты** в `<k>.audio` + `<k>.mime`. **Индекса нет**: имя файла — `key(ref)`, а он
  заменяет все не-буквы на `_` (`sc:12/3` → `sc_12_3`), то есть **по файлу нельзя восстановить ни ref, ни название
  трека**. Для списка «что доступно офлайн» этого мало — нужен индекс (раздел 7.1).
- Вытеснение — по времени изменения файла (`evict_in`), без «закреплённого».
- HLS склеивается только для fMP4/mp3; **MPEG-TS и зашифрованный AES-128 (HLS VK) не кэшируются** (`hls_parts`).
- Кнопки «Скачать» в `TrackMenu.svelte` **нет** (только автокэш). Автокэш по умолчанию **выключен**
  (`storage.cache_tracks = false`). Значит, у большинства пользователей в офлайне на ПК будут одни локальные файлы.
- Метаданные треков есть в таблице `tracks` (`upsert_tracks` зовут почти все команды), но «почти» — не гарантия.
- Нет детектора сети вообще (ни `navigator.onLine`, ни аналога в Rust).

**iPhone (`ios/Sonar/`):**
- `DownloadStore` качает **только прямой файл** (mp3 / FLAC / m4a). SoundCloud почти весь HLS — тогда берётся
  двойник из Яндекса или прямой mp3 SC, **иначе «Этот трек нельзя скачать»**. То есть для SoundCloud-слушателя
  офлайн-медиатека будет дырявой — это критический путь iPhone-этапов (3–4).
- Скачивание идёт в `URLSession(configuration: .default)` — **не фоновая**: свернул приложение — загрузка встала.
  Для «скачать 200 треков заранее» этого мало.
- Обложки — `AsyncImage` + `URLCache` (до `storage.covers_limit_mb`, 256 МБ), **в файле скачанного трека обложки нет**.
  Тексты — `LyricsCache` с **сроком жизни** (неделя / две у Любимых) — в офлайне протухший текст пропадёт.
- Уже есть `NetworkStatus` (`NWPathMonitor`, `isOnline`, `isUnmetered`) и `WaveCachePlan.nextPlayable` — переиспользуем.
- Кэша «прослушанное на диск» на iPhone нет (`docs/PLATFORMS.md`, «Осталось только на ПК»).

## 4. Настройка

### 4.1 Ключ и хранение

| Ключ | Значения | По умолч. | sync |
|---|---|---|---|
| `general.offline` | bool — «Офлайн-режим» | `false` | **нет** |
| `storage.download_wifi_only` | bool — скачивать только по безлимитной сети (раздел 8.2) | `true` | нет (префикс `storage.`) |

- **Не синхронизировать.** По умолчанию неизвестный `general.*` **синхронизируется**: в `store/sync.rs` локальны только
  `LOCAL_SETTINGS` и префиксы `system. update. storage. sync. remote.`, на iPhone — `SyncModels.swift` `localSettings` /
  `localPrefixes`. Добавить `general.offline` в **оба** списка, иначе после появления сервера включение в роуминге
  на телефоне выключит музыку дома на ПК.
- **Читать первым при старте.** Флаг должен быть известен до того, как стартует любая сетевая задача:
  ПК — до проверки обновлений, синка, ленты новинок, обновления правил текстов, списков «Для тебя»; iPhone — до
  `UpdateChecker`, `ReleaseNotifier`, `SelfUpdater`. Иначе первые запросы улетят в роуминг до того, как режим «включится».
- На ПК владелец флага — Rust (`offline.rs`, `AtomicBool` + событие `offline-changed`), интерфейс его **зеркалит**
  (как `settings`); на iPhone — `OfflineMode` (`@Observable`) в `Core/`, значение — в `SettingsStore`.

### 4.2 Где в интерфейсе

- **ПК:** Настройки → Система → Общее (`pages/settings/General.svelte`), новая карточка **«Сеть»** сверху (над «Медиатекой»).
  Строка «Офлайн-режим», подсказка: «Sonar не выходит в интернет и показывает только скачанные и локальные треки. Для
  роуминга и слабой сети». Ниже, когда включено: «Доступно офлайн: N треков · X ГБ».
- **iPhone:** Система → Общее (`GeneralSettingsView`), новая `SystemSection` «Сеть» со `SystemToggle`, подсказка та же.
- **Поиск по настройкам (ПК):** строка в `lib/settings-catalog.ts` (раздел `system` / `general`), по образцу соседних;
  тест `settings-catalog.test.ts` не пропустит пункт без записи.
- **Быстро, не заходя в настройки** (этап 4, но индикатор — обязателен сразу): пункт «Офлайн-режим» в меню трея
  (`tray.rs`), команда в Ctrl+K (`app/QuickOpen.svelte`), на iPhone — строка в Медиатеке и плашка (ниже).

### 4.3 Индикатор — обязателен

Пользователь должен **видеть**, что режим включён, иначе он решит, что приложение сломалось.
- ПК: плашка «Офлайн» в шапке окна рядом с поиском, клик — выключить (всплывашки открываются и закрываются **только
  кликом** — правило проекта). В мини-плеере и мини-окне — точка, без текста.
- iPhone: капсула «Офлайн» над контентом Медиатеки и в полном плеере; тап — выключить. Сворачивается вместе
  с `BottomChrome` при прокрутке.
- Анимации — общие приёмы (`motion.ts`, `use:indicator`; iPhone — `Motion`); при «Меньше движения» — только прозрачность.

## 5. Гарантия «ни байта»

Это сердце задачи. «Скрыть кнопки» не считается — важно, что **физически нет трафика**.

### 5.1 Что отключается, что остаётся

| Что | В офлайне |
|---|---|
| Воспроизведение не доступного офлайн трека | **нельзя**, ошибка «Нет в офлайне» (не сетевая) |
| Поиск по сервисам, единый поиск, подсказка-дописывание, «Найти в сервисах» | заменён локальным поиском (6.2) |
| Главная: Sonar Mix, «Для тебя», новинки (`release_feed`, колокольчик) | заменена офлайн-главной (6.1) |
| Страницы артиста и альбома, импорт по ссылке, перенос плейлистов сервисов, фантомные плейлисты | скрыты |
| Вход в сервисы, «Вручную», проверка ключа, **обновление токенов**, `sc_repair`, `public_client_id`, YouTube `visitorData`, Spotify TOTP | остановлены |
| Синхронизация, отправка прослушиваний и «сейчас играет» (`plays`, будущий `POST /events`) | копятся, уходят после выхода из режима |
| Тексты: lrclib / Genius / NetEase, перевод, аннотации, обновление правил (`updates/lyrics-rules.json`) | только то, что в кэше |
| Обложки с CDN, аватары исполнителей, баннеры | только локальные, иначе заглушка |
| Обновление приложения | **полностью**: проверка, **автоскачивание** (`update.auto_download` по умолчанию `true`!), changelog |
| iPhone: фоновая проверка новинок (`BGAppRefreshTask`) | задача просыпается и сразу выходит |
| «Отправить лог» (журнал ошибок) | недоступно, пока режим включён |
| Внешние ссылки (Сайт, Телеграм, «Открыть в …»), оплата | не открываются (клик по ссылке в роуминге — это тоже трафик) |
| Spotify librespot (своя сеть, сборка `spotify-playback`) | не запускается |
| **Остаётся:** локальная база, лайки, плейлисты, очередь, DSP (эквалайзер, эффекты, «Для этого трека»), статистика и итоги, умные плейлисты, дубли, экспорт в файл | работает |
| **Остаётся (локальная сеть, не интернет):** пульт iPhone ↔ ПК по Wi-Fi (`remote/`, mDNS), OBS-плашка, оверлей, Discord RPC (локальный IPC) | работает |

### 5.2 Механизм

**ПК.** Сеть выходит из пяти мест:
1. `Core.http` (`services.rs:154`) — основной `reqwest::Client`; его получают провайдеры, тексты, `sync.rs`, `crashlog.rs`,
   `stream.rs` (`/seg`, `/cover`, `/hls`), `gvideo.rs`.
2. `tauri-plugin-updater` — свой клиент, мимо `Core.http`.
3. WebView: `lib/updater.svelte.ts` ходит `fetch(CHANGELOG_URL)` и `fetch(RELEASES_URL)` напрямую; CSP в `tauri.conf.json` — `null`, то
   есть **браузер ничего не запретит**.
4. Окна входа (`login.rs`, WebView с сайтом сервиса).
5. Свои сети: `librespot` (опционально), `tokio-tungstenite` + `mdns-sd` (пульт — локальная сеть, не трогаем).

Решение — три пояса:
- **Ворота в одном месте:** все клиенты строятся через общий `net::client_builder()`, внутрь которого встроена проверка
  `offline::is_on()` на уровне соединения (кандидаты: `connector_layer` или свой `dns_resolver` у `reqwest::ClientBuilder` — **сверить с docs.rs
  для 0.13 на спайке**, API не проверял). Критерий выбора — **повторное использование уже открытого keep-alive
  соединения тоже должно блокироваться** (иначе запрос уйдёт по старому сокету в момент включения).
- **Команды:** каждая сетевая `#[tauri::command]` сразу возвращает `AppError::Offline` («Нет доступа к сети: включён
  офлайн-режим»). Окна входа и обновление не открываются/не стартуют.
- **WebView:** `updater.svelte.ts` и любой новый `fetch` — через `if (offline.on) return`. Плюс тест-сторож (по образцу
  `i18n-coverage.test.ts`): падает, если в `windows/src` появился `fetch(` / `XMLHttpRequest` / `<img src="http…">` вне списка разрешённых
  файлов. Сделано — `windows/src/lib/offline-net.test.ts`: `fetch` только в `updater.svelte.ts` (закрыт проверкой режима) и
  `quick-core.ts` (функция-параметр, не сеть). Обложки в `<img>` раньше шли прямо с CDN; теперь каждый `<img>` берёт адрес через
  `offline.src(url)` — в офлайне это локальный `/cover` (из кэша на диске, без кэша — ошибка, картинка прячется), тест это сторожит.

В момент включения: отменить идущее — `PREFETCH_GEN++`, склейку HLS (`cache_hls`), загрузки «Скачать», запросы текстов.
Сделано на ПК: тела ответов CDN в `stream.rs` (`proxy`, `proxy_cached`, YouTube) обёрнуты в `cut_offline` — перед каждым
куском смотрят на флаг и обрываются, недописанный файл в кэш не ложится; подкачка волны проверяет флаг на каждом куске;
`librespot` (свои сокеты мимо `net.rs`) закрыт `offline::guard()` в `spotify_play::ogg`. Интерфейс ждёт флаг из Rust
(`offline.init()` в `main.ts`) до первого кадра — картинки не успевают уйти на CDN.
Не закрыто: клиент, взятый из `core.http()` до включения, в цепочке из нескольких запросов (`with_sc`, тексты) может
доделать её по старому keep-alive; локальный файл на отключённом диске считается доступным, пока его не уберёт сканер.

**iPhone.** `URLSession` встречается в 17 файлах (`UpdateChecker`, `SelfUpdater`, все провайдеры, `LyricsSources`, `APIClient`,
`ReportBot`, `FileDownloader`, `Theme.swift`, `PlaybackEngine.swift`, `RecapView`…), у части — свои сессии.
- Единая фабрика `Net.session(_:)` и `URLProtocol`-сторож `OfflineGuard`: на `http/https` при включённом режиме отдаёт
  `URLError(.notConnectedToInternet)`. Регистрируется для `URLSession.shared` и **добавляется в `protocolClasses` всех
  своих сессий** (`DownloadStore`, `SelfUpdater`). Нюанс: кастомный `URLProtocol` обходит `URLCache` — поэтому сторож **сначала отдаёт
  ответ из `URLCache.shared`, если он там есть** (иначе в офлайне пропадут и закэшированные обложки), и только потом падает.
- `AVPlayer` / `AVURLAsset` через `URLProtocol` **не ходят** — поэтому запрет и в `PlaybackEngine.source(for:)`: в офлайне
  возвращается только локальный файл, иначе `OfflineError`.
- `ReleaseNotifier.refresh` и `UpdateChecker` проверяют флаг первой строкой.

### 5.3 Как проверить, что байтов нет (приёмка)

- Тест на Rust: локальный TCP-слушатель считает входящие соединения; включили режим — прогнали команды (поиск, текст, синк, обновление)
  — **ноль соединений**, включая второй запрос по уже открытому соединению.
- XCTest: `OfflineGuard` с заглушкой `URLProtocol`, плюс тест «в офлайне `PlaybackEngine` не берёт сетевой источник».
- Руками, ПК: Resource Monitor → Network (или Wireshark) — 10 минут простоя и 30 минут проигрывания скачанного: ноль исходящих
  от `sonar.exe`; то же **после перезапуска приложения в офлайне**.
- Руками, iPhone: Настройки → Конфиденциальность → **Отчёт о конфиденциальности приложений** (Network Activity) — Sonar не должен
  обращаться ни к одному домену, пока режим включён.
- Необязательный, но полезный для доверия счётчик «Запросов заблокировано с включения: N» в Хранилище / отладке.

## 6. Что видно и как себя ведёт

Правило: **экраны не пропадают, но наполнены только доступным офлайн.** Скрытие — только на показе, **ничего не пишется
обратно** в плейлисты и Любимые (иначе правка в отфильтрованном виде затёрла бы скрытые треки).

### 6.1 Главная
Офлайн-главная вместо Sonar Mix и «Для тебя»: «Недавно играло» (из `plays`, только доступное), «Любимые офлайн»,
«Скачанное», кнопка «Перемешать всё доступное». Поле точек `SonarField` и героя оставить как есть (локальная графика).
Sonar Mix «по доступному» (волна, у которой пул — только офлайн-треки, ранжирование по локальным сигналам и тегам из `tracks.tags`) —
этап 4; в первом выпуске его нет, чтобы не изображать «умную» волну на пяти треках.

### 6.2 Поиск
Только локальный: по названию, исполнителю, альбому среди доступных офлайн (`LIKE` по `tracks`, объединённой с индексом).
Подсказки-дописывание и вкладка «Все» (единый поиск) отключены; сервисных вкладок нет; в пустом результате — «В офлайне ищем
только среди скачанного и локального».

### 6.3 Медиатека
- **Любимые** — только доступные; заголовок «12 из 40 · офлайн».
- **Скачанное** (на ПК появляется) и **«На этом компьютере»** — как сейчас.
- **Свои плейлисты** — треки отфильтрованы; плейлист без единого доступного трека **скрыт**; перестановка и «✎» отключены
  (см. правило выше), «Убрать трек» — по `ref`, безопасно.
- **Фантомные плейлисты сервисов, «Перенос», импорт по ссылке** — скрыты целиком.
- **Альбомы и Исполнители:** вкладки в первом выпуске **скрыты** (честнее, чем пустые). Этап 4: показывать альбом/исполнителя,
  у которых ≥1 доступный трек, как список этих треков из локальной базы (`album_json`, `artists_json`).
- Карта исполнителей, страницы артиста и альбома — недоступны.

### 6.4 Плеер и очередь
- Очередь и «Далее» показывают **только доступное**; восстановление очереди при запуске (`general.restore`) фильтрует
  недоступное (на ПК уже есть образец — `playableQueue` в `lib/local.ts` для пропавших локальных файлов).
- `general.similar_autoplay` в офлайне берёт следующих **из доступных** (перемешанных из того же контекста), а не из сети.
- Эффекты, эквалайзер, скорость, «Для этого трека», таймер сна, медиа-клавиши — как обычно.
- Текст песни: из кэша; нет — «Текст недоступен офлайн». Срок жизни кэша текстов в офлайне **игнорируется** (отдаём
  протухшее), скачанным трекам текст сохраняется навсегда (раздел 8.2).
- Обложки: локальные; нет обложки — нейтральная заглушка и цвет темы по умолчанию (палитра из обложки считается только локально).

### 6.5 Настройки
Карточки сервисов: «Войти», «Вручную», «Отключить» неактивны с подсказкой «Недоступно в офлайне». Подписка и оплата — те же.
Статистика, итоги, умные плейлисты, дубли, экспорт — работают по локальной базе.

### 6.6 Ошибки
Единый текст вместо сетевых: «Нет в офлайне — скачай трек, пока есть сеть». Красных «не удалось подключиться» в этом режиме
быть не должно.

## 7. Данные: что значит «доступно офлайн»

### 7.1 ПК
Новая таблица (миграция **№ 16**, на устройстве, в синк не идёт — как `local_files`; обновить `docs/DB.md`):

```sql
CREATE TABLE offline_tracks (
  ref          TEXT PRIMARY KEY,     -- sc:123 | ym:456 | yt:…
  file         TEXT NOT NULL,        -- имя файла в папке кэша
  mime         TEXT NOT NULL,
  bytes        INTEGER NOT NULL,
  quality      TEXT,                 -- «MP3 320», «FLAC · Яндекс»
  kind         TEXT NOT NULL,        -- 'pinned' (скачал сам) | 'cache' (осело само) | 'wave'
  added_at     INTEGER NOT NULL,
  last_played  INTEGER,
  meta_json    TEXT NOT NULL         -- снимок Track: название, артисты, альбом, обложка, длительность
);
```
- **Снимок метаданных обязателен**, а не `JOIN tracks`: строку в `tracks` могут обновить или стереть, а офлайн-список обязан показывать название.
- **Скачанное лежит отдельно** (`<кэш>/pinned/`), автокэш — как сейчас (`<кэш>/tracks`): вытеснение `evict_in` его просто не видит.
  «Закрепить» уже закэшированный трек — переименование внутри одного тома. Лимит кэша (`storage.cache_limit_mb`) считается без скачанного.
- Запись и удаление файла и строки — в одной операции; при старте индекс сверяется с диском (файла нет — строка уходит,
  файл без строки — удаляется, как сейчас `.part`).
- Обложка закреплённого трека хранится **вместе с ним** и **исключена из `prune_covers`** (иначе кэш обложек в 300 МБ вытеснит её).
- Для скорости в памяти — `HashSet<String>` доступных `ref` (копия индекса, как `Core::local`); интерфейс получает
  `api.offlineRefs()` + событие `offline-index-changed`. Поле `available` у `Track` **не трогаем** — там другой смысл
  («файл на диске пропал»).
- **Резерв через двойника:** `track_alias` (миграция № 11) связывает SC-трек с его Яндекс-копией. Если в офлайне есть копия — SC-трек
  считается доступным, а `stream.rs` в офлайне подменяет `ref` на двойника **до** `track_cache::lookup`. Сейчас `lookup` идёт по исходному `ref`,
  и сыгранное через резерв ляжет под ключом двойника — **как именно ключуется кэш в `services/fallback.rs`, проверить** до реализации.
- Предикат — чистый, в `lib/offline-core.ts` (тесты vitest): `isAvailable(ref, set)`, `filterTracks`, `filterQueue`,
  `summary(total, available)`.

### 7.2 iPhone
- `isAvailableOffline(ref) = DownloadStore.localURL(ref) != nil || WaveCache.localURL(ref) != nil` (в `Playback/PlaybackEngine.swift`
  уже есть такой `isLocal`; вынести в `OfflineAvailability`).
- К файлу скачанного добавить рядом **обложку** и **текст** (раздел 8.2); `TrackRow` для скачанного берёт файл обложки без сети.
- Список `downloads.json` уже хранит `Track` целиком — снимка метаданных достаточно.
- `WaveCache` лежит в `Caches/`, iOS может почистить при нехватке места — в офлайне считается доступным, пока файл есть.
- Чистая логика (`OfflineFilter`, `OfflineGuard`, `OfflineAvailability`) — в `Core/` без UIKit, чтобы её гонял Swift на Linux (правило проекта).

## 8. Скачивание — без него режим пустой

### 8.1 ПК: новое
- **«Скачать»** в `TrackMenu.svelte`; у списков (`PlaylistMenu.svelte`): «Скачать плейлист», «Скачать все Любимые», у альбома — «Скачать альбом».
  Перед пачкой — подтверждение с размером и свободным местом («124 трека · ~1,0 ГБ · свободно 41 ГБ»); пачка >50 треков или
  >1 ГБ без подтверждения не стартует.
- Очередь скачивания: по 2 трека, пауза/возобновление, повтор после ошибки, состояния на строках («в очереди», «качается», «скачано»), общий
  прогресс в «Хранилище». Включили офлайн-режим — очередь **встаёт на паузу** и продолжится при выходе.
- Использует тот же код, что `prefetch` (`stream.rs`): `core.resolve` → файл или HLS-склейка → `Writer` → индекс. Качество — по
  `audio.quality`. Отдельная настройка качества скачивания — позже.
- Хранилище → новая карточка «Скачанное»: N треков, размер, «Удалить все» (с подтверждением, как у iPhone), «Показать в папке».
  `storage.cache_tracks` для скачанного **не нужен**: оно не зависит от автокэша.
- Не скачивается: MPEG-TS HLS и зашифрованный HLS VK (`hls_parts`) — честная подпись «Этот трек нельзя скачать».

**Сделано на ПК (этап 2, 2026-11-23).** Очередь — `downloads.rs` (в памяти, по 2; пауза, офлайн и отмена обрывают начатое и
возвращают его в начало очереди; «нельзя скачать» не повторяется); файлы — `<кэш треков>/pinned` (`track_cache`, LRU их не трогает),
обложки — `pinned/covers` (`stream.rs`), текст — в `lyrics_cache`, чистка и «Очистить тексты» не трогают тексты скачанного. Фронт —
`lib/downloads.svelte.ts` (зеркало `downloads-changed`), чистые помощники — `lib/downloads-core.ts` (оценка размера по `audio.quality`,
порог подтверждения), карточка «Скачанное» — `pages/settings/Storage.svelte`, значки на строках — `TrackRow.svelte`.
Пока **не сделано**: очередь не переживает перезапуск; «только по Wi-Fi» (`storage.download_wifi_only`) — нет детектора стоимости
подключения на ПК; перевод текста в пакет не кладётся; трафик обложек и текстов в подтверждении отдельно не показан; отдельного качества
скачивания нет.

### 8.2 Пакет на трек (оба): аудио + обложка + текст

Один «Скачать» тянет **три вещи**: аудио, обложку и текст. Иначе в дороге останутся треки без картинки и без караоке, а добрать это
без сети нельзя. Трафик пакета — почти целиком аудио (ориентиры: трек ~8 МБ в mp3 320, обложка 50–200 КБ — оценка из комментария
в `stream.rs`, текст единицы КБ — оценка, не замер).

**Обложка.**
- **Сжимать на устройстве и «разжимать» не нужно.** JPEG уже сжат: пережатие даст потерю качества и копейки выигрыша, а «разжимать» при
  показе и так делает декодер. Лишний код и CPU ради ~1 % места.
- Приложение **уже берёт компактные размеры**: SoundCloud `…-t500x500.jpg` (`providers/soundcloud.rs`), Яндекс `…/400x400` (`providers/yandex.rs`).
  Качаем **один** размер — тот, что и так показывается; несколько размеров на трек не качаем. Качество полноэкранной обложки в офлайне
  не хуже, чем онлайн.
- **Один файл на альбом, а не на трек:** ключ обложки уже умеет схлопывать размеры и вариации адреса (`cover_key`, `store/covers.rs`).
  Закреплённые треки одного альбома ссылаются на один и тот же файл; на iPhone — тот же приём (файл по хэшу ключа).
- Арифметика: 1000 треков ≈ 8 ГБ аудио против ≤ 100 МБ обложек даже **без** дедупа. Если когда-нибудь захочется ещё меньше —
  перекодировать в WebP/HEIC (~−30 %) — но это не сейчас.
- Закреплённая обложка защищена от вытеснения (`prune_covers`, лимит 300 МБ на ПК; `URLCache` на iPhone).

**Текст.**
- Качаем **тот текст, который приложение показало бы онлайн**: синхронизированный (караоке), иначе простой; вместе с источником. Сдвиг текста на
  трек (`lyrics_offset`) и караоке — локальные, работают без сети.
- Не нашёлся — **сохраняем отметку «текста нет»** навсегда (в `lyrics_cache` это `json = NULL`), чтобы в офлайне не крутилось «ищем текст».
- Перевод (`lyrics/translate.rs`) — только если перевод у пользователя включён. Аннотации Genius — не качаем (объём, в дороге не нужны).
- **Три подводных камня, найденных в коде:**
  1. `Store::prune_lyrics` при **каждом запуске** удаляет тексты, которых не открывали неделю (у Любимых — две). Поездка на месяц = тексты
     скачанных треков пропали. Тексты треков из `offline_tracks` (`kind = 'pinned'`) из чистки исключить; на iPhone — то же для `LyricsCache`.
  2. `UPGRADE_TTL_MS` (3 дня): простой текст пытаются заменить синхронизированным — в офлайне такой повтор пропускать, отдавать что есть.
  3. Срок жизни кэша текстов на iPhone — неделя / две у Любимых (`docs/SETTINGS.md`): в офлайне срок игнорируется.

**Защита от случайного скачивания в роуминге.** Настройка `storage.download_wifi_only` (по умолчанию `true`, не синхронизируется): пачка идёт
только по безлимитной сети. iPhone — уже есть `NetworkStatus.isUnmetered`; на ПК детектора нет — Windows умеет отдавать «стоимость подключения»
(`ConnectionProfile.GetConnectionCost`, **проверить на спайке**). Окно подтверждения пачки показывает трафик отдельно: «~1,0 ГБ аудио +
~40 МБ обложек и текстов».

### 8.3 iPhone: доработки существующего
1. **HLS SoundCloud → файл.** Без этого — дыра на главном сервисе. Два пути, **выбор — по результатам спайка на устройстве**:
   - **A. Склейка** как на ПК (`cache_hls`): init + куски fMP4 или mp3 в один файл. Одинаково с ПК, но **не проверено, что `AVPlayer`
     корректно играет и перематывает локальный fMP4**, собранный склейкой.
   - **B. `AVAssetDownloadURLSession`** — штатный офлайн для HLS у Apple (`.movpkg`, работает в фоне). Нужен свой формат хранения
     и проверка, что пускает подписанные ссылки SoundCloud и нужные заголовки.
   Рекомендация: начать со спайка B (меньше своего кода), A — запасной.
2. **Фоновая сессия** (`URLSessionConfiguration.background`) для самой передачи; ссылку на файл запрашивать **незадолго до** старта — подписанные
   ссылки Яндекса протухают. Что уже стартовало — докачается в фоне, остальное ждёт открытия приложения; в окне пачки честная подпись
   «Не закрывай Sonar, пока качается». Права `UIBackgroundModes` (`audio`, `fetch`) для фоновой сессии не нужны, но
   `nsurlsessiond` ограничен системой — **реальные пределы проверить на устройстве**.
3. Проверка **свободного места** перед пачкой (`volumeAvailableCapacityForImportantUsage`).
4. Обложка и текст в пакете — п. 8.2.
5. Этап 4: «Автоскачивать Любимые» (`storage.auto_download_liked`, по умолчанию выкл., только Wi-Fi, с лимитом ГБ и подтверждением).

## 9. Переходы

**Включение:**
1. Если играет трек, недоступный офлайн, — плавное затухание и пауза (не обрыв); играть автоматически следующий доступный **не начинаем**
   (пользователь только что выключил сеть, пусть сам решит). Если доступен — играет дальше.
2. Очередь пересобирается без недоступных; текущий трек остаётся, если доступен.
3. Отменяются идущие сетевые задачи (5.2), запросы синка и отправки прослушиваний встают в очередь.
4. Появляется индикатор, главная/поиск/Медиатека перерисовываются каскадом.

**Выключение:**
1. Индикатор уходит; фильтры снимаются.
2. Один раз **сбрасывается накопленное**: `plays` пачкой, правки лайков и плейлистов (когда будет сервер — синк; до сервера — ничего).
   Серверный предел: события старше 7 дней сервер отбросит (`docs/API.md`, `POST /plays`) — при долгой поездке часть статистики потеряется.
   Это нормально, но надо знать.
3. **Не** запускаем одновременно обновление, ленту новинок и синк: по одному, с паузой, чтобы после роуминга не выстрелить пачкой запросов.
   Обновление приложения — по обычному расписанию, **не немедленно**.
4. Очередь скачивания продолжается.

**Сломалось что-то при включённом режиме** (например, не прочитали флаг): по умолчанию — **считать режим включённым**.
Лишний запрос в роуминге дороже, чем лишняя заглушка.

## 13. Честная оценка идеи

**Хорошо:**
- Задача реальная и понятная: в роуминге цена килобайта настоящая; у большинства плееров такого жёсткого «ни байта» нет — они «качают меньше», не «не качают».
- Половина основы уже есть: `DownloadStore` и `NetworkStatus` на iPhone, кэш и локальные файлы на ПК.
- Не завязано на сервер — делается до сервера, как весь остальной блок.

**Слабые места (без прикрас):**
- **Режим без контента бесполезен.** На ПК нет «Скачать», автокэш выкл.; на iPhone большая часть SoundCloud не скачивается. Если не решить
  п. 8.3 и 8.1, пользователь включит режим и увидит пустую Медиатеку. Это **главный риск**, а не интерфейс.
- **«Ни байта» — обещание, которое легко нарушить:** на ПК 5 независимых выходов в сеть, на iPhone 17 файлов с `URLSession` и `AVPlayer` мимо перехватчика.
  Каждая будущая фича с запросом — новая дыра. Без теста-сторожа гарантия протухнет за пару недель.
- **Ручной режим — легко забыть выключить** (и удивиться, что Sonar «сломался»). Отсюда обязательный индикатор.
- **Недоступное скрыто, а не серое** (решение владельца) — списки короче без объяснения, поэтому остаётся счётчик «12 из 40» (раздел 6.3).
  не нравится, серые строки с подписью «Нет в офлайне» — альтернатива, но противоречит твоему «просто не отображать».
- **Альбомы и Исполнители в первом выпуске скрыты** — осознанный урез, чтобы не растянуть этап.
- **iOS фоновые загрузки — система не даёт гарантий.** Пачка «скачай 300 треков перед вылетом» может потребовать открытого приложения на зарядке.

## 14. Что не проверено

- API `reqwest` 0.13 для блокировки на уровне соединения (`connector_layer` / `dns_resolver`), и ловит ли он keep-alive — **не проверял**, решает спайк.
- Играет ли `AVPlayer` локальный fMP4, собранный склейкой, и пускает ли `AVAssetDownloadURLSession` подписанные ссылки SoundCloud — **без устройства не проверить**.
- Реальные пределы фоновых загрузок iOS.
- Срок жизни `lyrics_cache` на ПК (на iPhone — неделя / две у Любимых, по `docs/SETTINGS.md`).
- Как `services/fallback.rs` ключует кэш при игре через двойника.
- Автоопределение роуминга на iPhone: публичного API, который надёжно сказал бы «мы в роуминге», **нет** (`CTCarrier` устарел). Поэтому режим ручной;
  можно только реагировать на `isExpensive` / `isConstrained` (уже есть в `NetworkStatus`).
- Размеры файлов — арифметика по битрейтам, не замер.
- **iPhone (этапы 3–5) проверен только сборкой и XCTest в CI (`ios.yml`), на устройстве не гоняли:** играет ли склеенный fMP4 / mp3 SoundCloud,
  докачивает ли фоновая сессия при свёрнутом Sonar, срабатывает ли автоскачивание Любимых при возврате Wi‑Fi.
- Автоскачивание Любимых (обе платформы): в лимит считаются скачанное и стоящие в очереди Любимые, но не стоящие в очереди чужие треки;
  уменьшение лимита ничего не удаляет — лишнее чистится руками в «Скачанном».
