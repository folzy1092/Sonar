# Админ-панель Sonar (с сервером, решение владельца 2026-11-17)

Одно место, где владелец управляет всем: сборками и их объявлением, аккаунтами, устройствами,
функциями приложения, рассылками. Сейчас эти вещи разбросаны: «рубильник» `updates/ios-update.json`
(ручной запуск CI с `announce`), админ-кнопки в боте (BOT.md §2.6г–д), команды из TZ §4.16. С сервером
всё это переезжает в админку сайта; бот остаётся быстрым пультом к тому же API.

**Делаем вместе с сервером** (ROADMAP — этап сервера). До него ничего из этого не строить — только не
закладывать в клиенты то, что потом помешает (адрес проверки обновлений уже не зашит намертво).

## 0. Что уже сделано (2026-11-22) — серверная админка

Вместо страницы на статическом сайте админка — **HTML-страницы самого сервера** (`server/sonar/admin/`, FastAPI +
Jinja + свой CSS, без JS и без сборщиков) на поддомене вроде `admin.<домен>` через Cloudflare Tunnel: тот же процесс,
что и бот (`python -m sonar`, порт `PORT`, слушает `127.0.0.1`). Корень `admin.*` ведёт в `/admin/`.

- **Вход** — свой админ, не аккаунт Sonar (таблица `admins`). При первом запуске создаётся заводской `folzy` со случайным
  паролем — он печатается один раз в журнал запуска (`WARNING sonar.web`), в коде его нет, в базе — только хэш
  argon2id (потерял — `python -m sonar.admin passwd`), флаг `must_change` — до смены пароля открыта лишь форма смены. Новый пароль — от
  10 символов, не логин и не заводской; смена закрывает остальные сессии. Сессия — cookie `sonar_admin` (httpOnly,
  SameSite=Strict, Secure за HTTPS, 12 ч, хранится хэшем в `admin_sessions`), CSRF-токен в каждой форме (до входа —
  парный cookie), лимит — 5 неудачных попыток за 15 мин на IP (`CF-Connecting-IP`) и на логин, неизвестный логин
  отвечает так же, как неверный пароль. Каждый неудачный или заблокированный вход пишется в журнал (`login_failed`: логин,
  IP, причина), не больше 200 записей в час — перебор не раздует базу. CSP без скриптов, `no-store`, запрет фреймов. Забыл пароль —
  `python -m sonar.admin passwd` на сервере (скрытый ввод, приём TG Store). Подтверждения входа в Telegram пока нет.
- **Пользователи** — поиск (логин, @username, #номер, Telegram — ник или числовой id), фильтры (активные за 7 дней, с подпиской / без,
  с Telegram / без, бан), сортировка; карточка: профиль, сервисы, статистика из `events`/`plays`, устройства
  (`sessions` + устройства из событий), история подписки, журнал. Действия: бан с причиной (закрывает все сессии) /
  разбан, смена логина (только админ, @username остаётся), выдать / продлить подписку (продление — с конца текущей).
- **Дашборд** — сегодня и период (сегодня, 7, 30, 90 дней, свои даты): **уникальные люди** — открыли плеер, из них
  слушали, «зашли просто так», треков (всего и на слушателя), регистрации, DAU / WAU / MAU, сервисы и платформы,
  треки и исполнители дня и периода, графики по дням (SVG с сервера). Sonar Deep: действующие по тарифам, новые,
  продления, кончатся за 7 дней, выручка, **прогноз на 30 дней** с пометкой «оценка» и вилкой — формула в
  `admin/dashboard.py` `forecast`. Данных пока нет (клиенты не шлют `POST /events`) — честные нули и «нет данных».
- **Настройки без деплоя** (`admin/prefs.py`, kv `setting:*`): регистрация, режим обслуживания и текст, выключатель
  Яндекса, объявление в меню бота, ссылки (сайт, канал, скачать). Бот подхватывает сразу, клиенты — `GET /config`.
  Приёмы: из TG Store — один декларативный список (ключ, подпись, умолчание, тип, подсказка) и журнал изменений; из
  LenguBot — разделы, опасное (удаления, рассылки) отдельно от переключателей.
- **Журнал** — `admin_audit`, страница «Журнал» (фильтр по действию, страницы по 100, неудачные входы в админку)
  и блок в карточке; «Скачать CSV» — `GET /admin/audit.csv` с тем же фильтром (UTF-8 с BOM — Excel открывает сразу).
- **Устройства пользователя** — в карточке: «Завершить» у каждой живой сессии и «Выйти везде» без бана (§3–4).
- **Свои сессии** — на странице пароля: где открыта админка (IP, браузер, когда) и «Закрыть остальные».
- Посмотреть локально на выдуманных данных: `python server/tools/admin_demo.py` → `http://127.0.0.1:8080/admin/`
  (база `server/data/demo.db`, настоящая не трогается).

Остальное ниже (сборки, устройства, флаги по аудиториям, рассылки, отчёты о сбоях) — следующие шаги.

## 1. Где и кто

- **Адрес:** `sonar.folzy.ru/admin` — та же страница сайта (`site/`, GitHub Pages), данные — через API
  `sonar-api.folzy.ru/admin/*`. Сайт статический, вся власть — на сервере: без админ-сессии API отвечает 403.
- **Кто:** только владелец (TZ §4.16: админ один). Вход — аккаунтом Sonar с `is_admin = 1` + подтверждение
  в Telegram (бот присылает «Вход в админку с <устройство> — Разрешить / Нет»), сессия админки короткая (12 ч),
  все действия — в журнал (§7) и в лог-группу.
- Вид — как сайт и приложение: стиль Sonar, всё анимировано, тёмная тема; на телефоне тоже удобно.

## 2. Сборки и объявления — «в два клика»

Главная задача (владелец): «объявлять новую сборку по двум кликам».

- **Список сборок** по платформам (Windows, iOS, Android): номер, версия, дата, коммит, что нового (из
  `changelog.json` / текста релиза), сколько устройств уже на ней. Новые сборки CI появляются сами
  (сервер читает релизы GitHub по вебхуку или раз в 5 мин).
- **Объявить:** клик по сборке → «Объявить» → окно: кому (все / бета / список аккаунтов / список устройств),
  «Что нового» (подставлено из коммитов, можно поправить), «Обязательное» (minimum_build — старые сборки
  просят обновиться и не работают без этого), «Разослать уведомление» (колокольчик + Telegram) → «Объявить».
  Это и есть два клика.
- **Каналы:** стабильный и бета (в приложении — Обновления → Канал). Сборка может быть объявлена в бету
  раньше, потом одним кликом «Перевести в стабильный».
- **Отозвать:** снять объявление (плохая сборка) — устройства, ещё не обновившиеся, её больше не получат;
  кто уже поставил — по желанию предложить откат на прошлую.
- **Своя сборка конкретным людям:** объявить сборку только выбранным аккаунтам или устройствам (проверка
  фикса у одного человека).
- **Как клиенты узнают:** `GET /updates?platform=ios&build=242&device_id=…&channel=stable` → сервер сам решает,
  что предложить этому устройству (канал, аудитория, обязательность). Пока сервера нет — прежний
  `updates/ios-update.json` / `update.json`; клиент сначала спрашивает сервер, недоступен — файл.
- Проверенные версии бота (BOT.md §2.6г) и «Актуальные версии» — тот же список: объявленная всем стабильная
  сборка = актуальная версия платформы.

## 3. Аккаунты

- Поиск по логину, `@username`, `#номеру`, Telegram; карточка: профиль, дата, сервисы (подключены ли, без
  токенов), статистика, устройства, обращения.
- Действия: сменить логин (только админ, TZ), бан / разбан (с причиной и сроком), выйти на всех устройствах,
  сбросить пароль (одноразовая ссылка в Telegram), выдать бету, удалить аккаунт (с подтверждением вводом логина).

## 4. Устройства и версии

- Все устройства всех аккаунтов: имя («iPhone 15 Pro», «Windows 10 (Folzy)»), платформа, версия и сборка,
  последний вход (BOT.md §2.6е–ж, API.md `/me/devices`). Фильтр «на старой сборке».
- Действия: завершить сессию устройства, заблокировать устройство (по `device_id` — UUID в Keychain / HWID),
  выдать устройству конкретную сборку.

## 5. Функции и «рубильники»

- **Флаги функций** (remote config): включить / выключить функцию всем, платформе, версии, аккаунту —
  например: «SoundCloud через Яндекс», источник текстов Genius, «Моя волна 2», новый плеер, вход через бота,
  регистрация. Клиенты получают `GET /config` при запуске и раз в час (там же — Discord APP_ID, адреса).
- **Аварийный выключатель:** выключить сервис целиком (Яндекс банит — «Яндекс временно недоступен» у всех,
  без ошибок в логах), режим обслуживания с текстом.
- **Умолчания настроек** для новых пользователей (те же ключи, что SETTINGS.md) — без выпуска сборки.

## 6. Рассылки и канал

- Уведомление в приложении (колокольчик) и/или Telegram — всем / аудитории (§2); предпросмотр.
- Пост в канал `@SonarUpdates` с кнопками (BOT.md §2.6д) — тот же редактор, что в боте, плюс шаблон
  «Новая версия» из объявленной сборки (кнопки Windows / iOS / Android сами).

## 7. Журнал и здоровье

- Журнал действий админки (кто, что, когда, было → стало).
- Отчёты о сбоях (журнал ошибок клиентов, `Отправить лог`) — списком с группировкой по причине и сборке;
  обращения «Баг / Идея» (BOT.md §2.10) — те же темы, ответ из админки.
- Статус сервиса (SPEC §3.11) и нагрузка сервера (ОЗУ, место, запросы) — с учётом ограничений Velt.

## 8. API (черновик, дополнит API.md)

`/admin/*` — только админ-сессия. `GET/POST /admin/builds`, `POST /admin/builds/{id}/announce`
`{audience, channel, notes, mandatory, notify}`, `POST /admin/builds/{id}/revoke`; `GET /admin/users`,
`POST /admin/users/{id}/{ban|unban|logout_all|set_login|reset_password}`; `GET /admin/devices`,
`POST /admin/devices/{id}/{revoke|block|pin_build}`; `GET/PUT /admin/flags`; `POST /admin/broadcast`;
`POST /admin/channel_post`; `GET /admin/audit`; `GET /admin/crashes`. Клиентам: `GET /updates`, `GET /config`.
