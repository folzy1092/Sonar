# Sonar — техническая спецификация

Как устроено то, что описано в `TZ.md`. API — `API.md`, база — `DB.md`, настройки —
`SETTINGS.md`, алгоритмы — `PSEUDOCODE.md`.

## 1. Архитектура

```
 iPhone (SwiftUI)                 Windows (Rust, позже)
   │  HTTPS + JSON                    │
   └──────────────┬───────────────────┘
                  ▼
        sonar-api.folzy.ru  (Cloudflare Tunnel, HTTPS от Cloudflare)
                  ▼
   Velt, контейнер Python 3.13 · один процесс (+ cloudflared)
   ┌───────────────────────────────────────────────┐
   │ FastAPI (uvicorn)       aiogram 3 (бот входа) │
   │   routers/  ──►  services/  ──►  SQLite       │
   │                   │ soundcloud.py             │
   │                   │ yandex.py  (yandex-music) │
   │                   │ lastfm.py                  │
   └───────────────────┼───────────────────────────┘
                       ▼
        api-v2.soundcloud.com · api.music.yandex.net · Last.fm
 Тексты: клиент ◄── lrclib, Genius напрямую (сервер не участвует)

 Аудио: клиент ◄── CDN SoundCloud / Яндекса напрямую (сервер аудио не трогает)
 Обновления: клиент ◄── raw.githubusercontent.com/folzy1092/Sonar/main/updates/*.json
                       ◄── github.com/folzy1092/Sonar/releases (IPA)
 selfbot ──► GET /oauth/now (Bearer ключ API)
 Публичный сайт: sonar.folzy.ru (GitHub Pages, папка site/) ──► GET /public/users/...
```

Принципы:
- **Сервер — источник правды** для аккаунта, библиотеки, настроек, статистики.
- **Токены сервисов живут только на сервере.** Клиент просит «дай поток для `sc:123`» —
  сервер ходит в сервис с токеном пользователя и возвращает короткоживущую ссылку на CDN.
- Клиент работает офлайн с локальной копией и очередью изменений.

## 2. Идентификаторы

- **Трек:** `TrackRef` = строка `"<src>:<id>"`.
  - SoundCloud: `sc:2296053116` (числовой id).
  - Яндекс: `ym:12345678` (id трека; альбом хранится в метаданных, нужен для ссылок).
- **Плейлист сервиса:** `scpl:<id>`, `ympl:<uid>:<kind>`. Плейлист Sonar — `pl_<ulid>`.
- **Контекст воспроизведения** (откуда играет, для статистики и `context` в `/oauth/now`):
  `favorites`, `playlist:<id>`, `wave`, `search`, `album:<ref>`, `artist:<ref>`, `queue`.

## 3. Сервер

### 3.1. Стек

| Что | Чем |
|---|---|
| HTTP | FastAPI + uvicorn (1 воркер) |
| БД | SQLite (WAL) через SQLAlchemy 2 async + aiosqlite, миграции Alembic |
| Бот | aiogram 3, long polling в том же процессе |
| HTTP-клиент | httpx (async), таймауты 10 с, ретрай 2× на сетевые ошибки |
| Яндекс | `yandex-music` (MarshalX) — поиск, плейлисты, лайки, похожие, download-info (без rotor) |
| SoundCloud | свой модуль на httpx к `api-v2.soundcloud.com` (опыт `sc_api` из selfbot) |
| Пароли | argon2-cffi (argon2id) |
| Шифрование токенов | `cryptography.fernet`, ключ `SONAR_FERNET_KEY` из env |
| Тесты | pytest + httpx `ASGITransport`, без сети (сервисы подменяются) |

### 3.2. Хостинг

- Хостинг — **Velt, «Контейнеры» → Python** (выбор 2026-11-12): 512 МБ ОЗУ, 10 % vCPU,
  NVMe 1–2 ГБ, 1 открытый порт, MySQL не нужен (SQLite). **Своих поддоменов у Velt нет**
  («Поддомены пока недоступны»). Старт: `python -m sonar` (uvicorn + бот + cloudflared).
- Код тянется из `main` при перезапуске (как selfbot), данные — `server/data/` (вне git).
- Бюджет ресурсов: Python-процесс ~110–140 МБ ОЗУ, cloudflared ~30–40 МБ — в 512 МБ с запасом.
  CPU 10 % — мало для тяжёлого: argon2 с параметрами `time_cost=2, memory_cost=19 МиБ`
  (вход ≈ 0,3–0,5 с — нормально), Pillow — только аватары 512×512, видео фона сервер **не**
  перекодирует (жмёт телефон). Диск: зависимости ~200 МБ, база ~40 МБ/год, аватары и фоны
  (≤ 8 МБ на пользователя) — при 1 ГБ впритык, **лучше взять 2 ГБ**.
- **Два адреса, разные задачи:**
  - **API** (`SONAR_PUBLIC_URL` = `https://sonar-api.folzy.ru`) — видят только приложения.
    Cloudflare Tunnel: `cloudflared` (бинарник в `server/bin/`, env `CF_TUNNEL_TOKEN`)
    сам выходит наружу к Cloudflare — **входящий порт и HTTPS на сервере не нужны**,
    сертификат даёт Cloudflare. Нужно один раз перенести DNS folzy.ru на Cloudflare
    (бесплатно; запись для GitHub Pages сайта folzy.ru переносится как есть и продолжает
    работать). Имя одноуровневое (`sonar-api`, не `api.sonar`): бесплатный SSL Cloudflare
    покрывает только `*.folzy.ru`.
    Почему не is-a.dev для API: Let's Encrypt на сервере требует порт 80/443 или правку TXT
    (у is-a.dev — через PR), а прокси Cloudflare is-a.dev пускает только на стандартные
    порты — у контейнера Velt порт произвольный. Туннель на своём folzy.ru проще и надёжнее.
  - **Публичный сайт** — ссылки «Поделиться профилем», страница скачивания:
    `https://sonar.folzy.ru` на **GitHub Pages** (папка `site/` этого репо).
    Решение владельца 2026-11-15: свой поддомен вместо is-a.dev. DNS folzy.ru: запись
    `CNAME sonar → folzy1092.github.io` **без прокси** Cloudflare (серое облако) — сертификат
    выпустит сам GitHub Pages; в `site/CNAME` — `sonar.folzy.ru`, в настройках Pages репо —
    Custom domain `sonar.folzy.ru` + Enforce HTTPS.
- Адрес API в iOS не зашит: `Info.plist` → `SonarAPIBaseURL` (меняется в сборке), плюс
  `updates/update.json` может объявить новый адрес (`api_url`) — на случай переезда.
- Требование iOS: `itms-services` манифест и все запросы — только HTTPS с валидным
  сертификатом (ATS), поэтому вариант «голый IP:порт» не рассматриваем.
- Бэкап: раз в сутки копия `sonar.db` (через `VACUUM INTO`) владельцу в Telegram.

### 3.3. Env

`SONAR_FERNET_KEY`, `SONAR_BOT_TOKEN`, `SONAR_OWNER_TG_ID`, `SONAR_PUBLIC_URL`,
`LASTFM_API_KEY`, `LASTFM_API_SECRET`, `YANDEX_OAUTH_CLIENT_ID`, `CF_TUNNEL_TOKEN`, `PORT`,

### 3.4. Аутентификация

- Сессия = случайный токен 32 байта (`secrets.token_urlsafe`), в БД — только SHA-256.
  Клиент шлёт `Authorization: Bearer <session>`. Токен бессрочный, пока не выйдешь/не отзовут;
  `last_seen_at` обновляется не чаще раза в 5 минут.
- Ключ API «сейчас играет» — отдельный токен (`sk_...`), даёт **только** чтение `/oauth/now`.
- Лимиты: вход по паролю — 5 попыток / 15 мин на логин и на IP; регистрация — 5 / час на IP.

### 3.5. Вход через Telegram

```
App ── POST /auth/telegram/start {purpose: login, device} ──► Server
App ◄── {request_id, link: t.me/<bot>?start=login_<secret>, expires_at}
App: показывает ссылку, [Скопировать] [Открыть] [Назад]; опрашивает
     GET /auth/telegram/poll/{request_id} каждые 2 с
Пользователь ── /start login_<secret> ──► Bot
Bot: аккаунт с этим tg_id есть? ── да ──► «Войти в Sonar на iPhone 15 Pro?» [Войти] [Это не я]
                                 └ нет ─► «Создать аккаунт @<username>?» [Создать] [Отмена]
Bot ── confirm ──► Server: request.status = approved, user_id
App ◄── poll: {status: approved, session, user}
```

Привязка (`purpose: link`) — то же, но запрос создаёт уже вошедший пользователь, и бот
просто записывает `tg_id` в его аккаунт.

**Обновлено 2026-11-15 (BOT.md):** вход в приложении **всегда сначала логин + пароль**. Бот
привязывается логином и паролем прямо в чате или **быстрой ссылкой** (5 мин, одноразовая):
её открывают там, где уже вошли, и подтверждают в окне «Авторизация в аккаунт» (кто получит
доступ, «Разрешить» активна через 3 с). Та же ссылка — вход на новом ПК/iPhone без пароля.
Схема выше с подтверждением в боте — заменена этой (BOT.md §3, API `/auth/link`).

### 3.6. Проксирование сервисов

`services/soundcloud.py` и `services/yandex.py` реализуют один интерфейс `Provider`:

```
search(q, kind, limit) -> [Track|Album|Artist|Playlist]
track(id) -> Track
stream(id, quality) -> StreamInfo{url, protocol: hls|progressive, codec, bitrate, expires_at, gain_db?}
user_playlists() -> [ServicePlaylist]       # фантомные
playlist_tracks(id) -> [Track]
user_likes() -> [Track]                     # тоже фантомный «плейлист»
related(id) -> [Track]
similar(id) -> [Track]                      # кандидаты для своей волны (SC = related)
home_blocks() -> [Block]                    # «Для вас», «Открытия»

```

- Метаданные треков кэшируются в таблице `tracks` (TTL 7 дней) — чтобы списки плейлистов
  отдавались без походов в сервисы.
- `stream` не кэшируется дольше `expires_at - 60 с`.
- SoundCloud: `client_id` + `OAuth <token>` пользователя; поток — `transcodings` → выбираем
  по качеству (HLS AAC 160 / Opus / MP3 128; 256 AAC при Go+).
- Яндекс: `download-info` → лучший кодек ≤ выбранного качества → подписанная ссылка
  (`md5(SALT + path[1:] + s)`, как в библиотеке). Нормализация — из поля `r128`, если есть.

### 3.7. «Моя волна»

**Решение владельца (2026-11-12): rotor Яндекса не используем.** Яндекс режет запросы из-за
границы (у владельца — Латвия; бан на 3600 с), а волна — самый «подозрительный» для них
поток запросов. Волна в Sonar — **своя, для всех**, сессия в памяти сервера (TTL 1 ч).

**Своя волна.** Простой и понятный алгоритм (псевдокод — `PSEUDOCODE.md` §11):
- кандидаты: похожие треки от сидов (последние лайки + последние дослушанные) — для `sc:`
  это `related` SoundCloud, для `ym:` — «похожие» Яндекса (`/tracks/{id}/similar`, если
  Яндекс доступен, см. §3.7а); плюс 10–20 % «разведки» — похожие от случайного старого лайка;
- сигналы из событий: дослушал (+), лайк (++), пропуск в первые 30 с (−), дизлайк (бан
  трека), повторный пропуск артиста подряд (артист на паузу на сессию);
- фильтры: не играть прослушанное за 7 дней, не ставить одного артиста два раза подряд,
  не больше 2 треков артиста на порцию из 10.

**Почему не Rust-движок `NoAffr4id/Dotify_Moya_volna_Ebal`** (смотрели 2026-11-12):
- это не клиент API Яндекса, а самописный рекомендатель (бандиты, марковские цепи,
  совместная встречаемость, HNSW-поиск по векторам);
- ему нужен каталог с **аудио-эмбеддингами**, жанром, BPM, кривой энергии для каждого
  трека — ни SoundCloud, ни Яндекс таких данных не отдают, ядро без них не работает;
- **нет лицензии** — по умолчанию все права у автора, копировать код нельзя;
- один коммит «Add files via upload», файлы без `src/`, как есть не собирается; и он на Rust,
  а сервер на Python.
Идеи (какие события учитывать, разнообразие, «разведка») — взяли в свою волну выше.

### 3.7а. Доступность Яндекса из-за границы — главный риск

Владелец получал бан на 3600 с, делая запросы к Яндексу из Латвии. Если Яндекс режет весь
API для нероссийских IP, это бьёт не только по волне, но и по поиску, лайкам и **потоку**
(`download-info`). Что делать — решается проверкой в этапе 1 (`server/tools/check_ym.py`
с сервера Velt и с ПК владельца), варианты по порядку:
1. **Работает с сервера как есть** — если бан был из-за «неправильного» клиента (нет
   заголовков `X-Yandex-Music-Client`, `User-Agent` приложения, слишком частые запросы).
   Тогда: правильные заголовки, кэш, не чаще 5 запросов/с на пользователя, бэк-офф на 429.
2. **Через прокси/VPS в РФ** — env `YANDEX_PROXY` (`socks5://…`), все запросы к
   `api.music.yandex.net` идут через него. Сами аудиофайлы CDN Яндекса обычно отдаёт и за
   границу — проверить; если нет, поток тоже через прокси (но это уже нагрузка на прокси).
3. **С устройства пользователя** — запросы к Яндексу делает приложение напрямую со своего
   IP (так работает Dotify). Не поможет, если блок по стране, а не по серверным IP.
4. Ничего не помогло — Яндекс в Sonar пока выключен (кнопка в «Сервисах» с замком), всё
   остальное работает на SoundCloud.
Сервер Velt — в **Германии** (2026-11-12).

**Проверка 2026-11-12 с ПК владельца (Латвия), `server/tools/check_ym.py` — всё работает:**
`/account/status` 200 (аккаунт регион 225, Плюс есть), поиск 200, `/similar` 200 (14 похожих),
`/download-info` 200 (mp3 192 и 320), сам mp3 — 206 с CDN. Заголовки клиента:
`X-Yandex-Music-Client: YandexMusicAndroid/24023621`, `User-Agent: Yandex-Music-API`.
Ранний бан на 3600 с был, судя по всему, от другого сервиса Яндекса, не от API Музыки.
Токен годится и старого формата (`AQAAAA…`), и нового (`y0_…`).

Что дальше: в субботу тот же скрипт **с сервера Velt (Германия)**. Пускает — оставляем как в
§3.6 (Яндекс через сервер: одна реализация на iOS и Windows). Не пускает — вариант 3. Если вариант 3 — провайдер Яндекса переезжает в клиент
(`ios/Sonar/Core/Providers/Yandex`), токен Яндекса тогда хранится в Keychain устройства и
синхронизируется через сервер зашифрованным, а сервер к Яндексу не ходит.

### 3.7б. Тексты песен (кнопка «T») — на устройстве, как в selfbot

Тексты ищет **само приложение на устройстве пользователя** (iPhone, компьютер), сервер в
этом не участвует: запросы к lrclib и Genius идут с IP пользователя, нагрузки на сервер
(10 % CPU) нет. Логика и имена — порт `selfbot/code/lyrics.py` + Genius-часть `ai_lyrics.py`,
структура максимально похожая (те же шаги, те же названия функций в camelCase):
1. **lrclib** (`fetchAny`): исполнитель + название + длительность → есть `syncedLyrics` →
   синхронный текст (караоке: строка подсвечивается, тап по строке — перемотка).
2. Нет — повтор с упрощённым запросом (без «(feat …)», `#тегов`, эмодзи, скобок), как
   `fetch_any` / `_sc_alternatives`.
3. В lrclib только `plainLyrics` или ничего → **Genius** (`geniusText`, `geniusQueries` — до 5
   запросов): песня берётся, только если её исполнитель совпадает; текст без
   «[Припев]»-заголовков → **обычный текст** без подсветки.
4. Нигде нет → «Текст не найден»; «нет» перепроверяется не чаще раза в 30 мин (`RECHECK_TTL`).
Кэш — на устройстве (экран «Хранилище» → «Тексты»). Сдвиг тайминга под трек —
`track_prefs.lyrics_offset_ms` (синхронизируется). Whisper/ИИ-тайминг из selfbot не переносим.
Модули: iOS — `ios/Sonar/Core/Lyrics/` (`Lyrics.swift`, `Lrclib.swift`, `Genius.swift`);
Windows — `windows/src/lyrics/` (`mod.rs`, `lrclib.rs`, `genius.rs`) — одинаковая раскладка.

### 3.8. Статистика

- Клиент шлёт `POST /plays` на каждое засчитанное прослушивание
  (`listened_ms ≥ min(30 000, duration/2)`), пачкой, с `played_at`.
- Сервер пишет в `plays`, скробблит в Last.fm (если включено), отдаёт агрегаты
  `GET /stats?period=day|week|month|half_year|year|all` (бот `/stats` берёт те же агрегаты напрямую из `domain/stats.py`) — считаются SQL-запросами на лету (объёмы
  крошечные: ~100 строк/день/пользователь).

### 3.9. «Сейчас играет»

- Клиент шлёт `PUT /player/state` при: старте трека, паузе/плее, перемотке, смене очереди,
  и раз в 30 с во время игры (heartbeat).
- Сервер хранит последнее состояние на пользователя (`player_state`), Last.fm
  `updateNowPlaying` — при смене трека.
- `/oauth/now`: если heartbeat старше 90 с, `is_playing=false`, `state="paused"`.
  `position_ms` экстраполируется: `position + (now - updated_at)`, если играет.

### 3.10. Синхронизация

- Каждая изменяемая сущность (лайк, плейлист, трек в плейлисте, настройки, состояние плеера)
  имеет `rev` — глобальный монотонный счётчик в БД (`sync_rev`).
- Клиент: изменения → локальная очередь операций (`ops`) → `POST /sync/push` пачкой.
  Ответ — новый `rev`. Конфликт по одному ключу — побеждает позднее `client_ts`.
- `GET /sync/pull?since=<rev>` → все изменения после `rev` (включая удаления — tombstones).
- Ручные кнопки: «Отправить» = `POST /sync/replace` (полный снимок с клиента),
  «Получить» = `GET /sync/snapshot` (полный снимок с сервера, клиент перезаписывает своё).
- Настройки — словарь `ключ → значение`; синхронизируются только ключи с пометкой
  `sync: true` в `SETTINGS.md` (вид и жесты — да; кэш, путь к сертификату — нет).

### 3.11. Статус сервиса (решение владельца 2026-11-15)

Страница статуса, команда бота `/status` и `GET /status` — одни и те же данные.

**Что проверяем** (фоновая задача сервера раз в **5 мин**, каждая проверка с таймаутом 5 с,
всё вместе — доли секунды CPU, укладывается в 10 % vCPU):

| Группа | Пункт | Как проверяем |
|---|---|---|
| Инфраструктура | 🖥️ Основной (API) | сам сервер: запрос к БД, ответ `/health` |
| | 🤖 Бот | цикл aiogram жив: последний опрос Telegram < 2 мин назад |
| | 📦 Хранилище | SQLite читается и пишется, свободного места на диске > 100 МБ |
| | 🌐 Сайт | `GET https://sonar.folzy.ru` → 200 |
| Платформы | 🌐 SoundCloud | поиск api-v2 с публичным client_id → 200 |
| | 🌐 Яндекс Музыка | `GET /search?text=…` с сервера → 200 (из Германии может быть ⚠️ — SPEC §3.7а) |
| | 📝 lrclib | `GET /api/search?q=…` → 200 |
| | 📝 Genius | `search/multi` → 200 (капча Cloudflare = ⚠️) |
| | 🎧 Last.fm | `chart.getTopTracks` с ключом → 200 |
| | ✈️ Telegram | `getMe` → 200 |

Плееры, которых у нас нет (Spotify, YouTube, VK, Deezer, Apple Music, МТС, Звук) — **не
показываем**: в списке только то, с чем Sonar реально работает (сейчас SoundCloud и Яндекс;
владелец планирует до 5 сервисов — новые появятся, когда их подключат).
**Для всех** — Основной, Хранилище, платформы, «Слушают онлайн», «Пользователей», аптайм.
**Только владельцу** (решение 2026-11-15) — ещё 🎵 Медиа (ссылки на поток SC/Яндекса выдаются),
🔀 Прокси (Cloudflare Tunnel отвечает снаружи), Бот, Сайт, тексты (lrclib, Genius), Last.fm,
Telegram и задержки в мс. Формат — BOT.md §4.

**Состояние пункта:** ✅ работает — последняя проверка прошла быстрее 2 с; ⚠️ с перебоями —
медленнее 2 с или упала 1–2 из последних 3; ❌ недоступен — 3 подряд не прошли.
**Общая строка:** всё ✅ → «✅ Все сервисы работают»; есть ⚠️ → «⚠️ Некоторые сервисы работают
с перебоями»; есть ❌ в инфраструктуре → «❌ Сбой: <что>».
**Аптайм** — доля успешных проверок «Основного» за 30 дней, два знака после запятой (99.99%).

**Хранение:** сырые проверки 7 дней (`status_checks`), дальше — по дням (`status_daily`), 90 дней
(DB.md). Смена состояния ✅ ↔ ⚠️ ↔ ❌ — сообщение владельцу в Telegram (лог-группа, дедупликация
10 мин, как ошибки в §8).

**Где видно:**
- `GET /status`, `GET /status/history?days=90` — API.md §9, без авторизации, кэш 30 с.
- Бот `/status` для всех — TZ §4.15 (дерево ├ └, как в примере владельца, кнопка «🔄 Обновить»
  правит то же сообщение, кнопка «Страница статуса»).
- `https://sonar.folzy.ru/status` (`site/status.html`, GitHub Pages): опрашивает
  `/status` раз в 30 с; полоски по 90 дням на каждый пункт. Сервер не отвечает — страница **сама**
  показывает «🖥️ Основной: ❌ Недоступен» (она живёт на GitHub, а не на нашем сервере).
  Всё анимировано: полоски вырастают, точки состояния мягко пульсируют, смена состояния —
  плавный переход цвета.
- В приложении: «О приложении» → строка состояния сервера (точка + «Все сервисы работают»).

## 4. iOS-клиент

### 4.1. Стек

| Что | Чем |
|---|---|
| UI | SwiftUI, iOS 18+, `@Observable` |
| Проект | XcodeGen (`ios/project.yml`) → `.xcodeproj` генерируется в CI |
| Сеть | URLSession + async/await, свой `APIClient` |
| Локальные данные | SwiftData (кэш библиотеки, очередь ops), Keychain (сессия, P12) |
| Аудио | AVQueuePlayer (бесшовность), AVAudioSession `.playback` |
| Системный плеер | MPNowPlayingInfoCenter + MPRemoteCommandCenter |
| Картинки | свой кэш (NSCache + диск), downscale |
| Подпись (автообновление) | zsign + ZipArchive (из Shadow) |
| Зависимости | SwiftPM; минимум сторонних |

### 4.2. Модули (папки внутри `ios/Sonar/`)

`App` (вход, DI, навигация) · `Core` (APIClient, модели, хранилище, синк) ·
`Playback` (движок, очередь, кэш аудио, now playing) · `DesignSystem` (тема, стекло,
компоненты, цвет обложки) · `Features/*` (экраны) · `Update` (порт ShadowSelfUpdate) ·
`Resources` (строки ru/en, иконки). Подробно — `MAP.md`.

### 4.3. Воспроизведение

- `PlaybackEngine` держит `AVQueuePlayer`, заранее подгружает следующий элемент
  (за 15 с до конца) → бесшовность.
- Ссылка на поток берётся у сервера перед загрузкой элемента; при ошибке 403/410 —
  ещё раз (ссылка протухла), потом — пропуск трека с тостом.
- HLS (SoundCloud) играет AVPlayer нативно. Кэш HLS — `AVAssetDownloadURLSession`;
  progressive (Яндекс) — обычная загрузка файла.
- Нормализация: `AVMutableAudioMix` с громкостью `10^(gain_db/20)`, где `gain_db` —
  `-14 LUFS - loudness трека` (у Яндекса `r128`; у SC — нет данных, без коррекции).
- «При уведомлении»: обработка `AVAudioSession.interruptionNotification` → приглушить /
  пауза / ничего.
- **Скорость:** `player.rate` (0.5–2.0, шаг 0.25) + `item.audioTimePitchAlgorithm =
  .timeDomain` — тон не меняется. «Запомнить» → `track_prefs[ref].speed` (синхронизируется,
  тип `track_pref` в синке; там же потом сдвиг текста). При загрузке трека: есть запомненная
  скорость — ставим её, иначе 1.0. Экран «Кэш» → «Настройки треков — Сбросить» чистит всё.

### 4.3а. Вход в Яндекс «в один клик»

`WKWebView` в листе открывает
`https://oauth.yandex.ru/authorize?response_type=token&client_id=<id Яндекс Музыки>`.
`WKNavigationDelegate` ловит переход на `music.yandex.ru/#access_token=...` — достаёт
`access_token` (`y0_...`), закрывает лист, шлёт `PUT /services/yandex {token}`.
`ASWebAuthenticationSession` не подходит: https-колбэк требует associated domains на
`music.yandex.ru`, а они не наши. client_id — константа на сервере (`GET
/services/yandex/oauth-url`), чтобы поменять без обновления приложения.

### 4.4. Тема под обложку

- `CoverColorExtractor`: обложка → 64×64 → квантование (k-means, k=5) → выбираем кластер с
  лучшим `saturation × sqrt(share)`, отбрасывая почти чёрные/белые → акцент.
- Для фона — тот же цвет, затемнённый до L=12% (тёмная тема) или осветлённый до 92%.
- Контраст текста на акценте: если < 4.5:1 — текст чёрный/белый, что контрастнее.
- `ThemeStore.accent` анимируется `withAnimation(.easeInOut(0.4))`; все компоненты берут цвет
  только из `ThemeStore` — тогда перекрашивается весь интерфейс.

### 4.5. Навигация

Таб-бар (стиль: стандартный / закруглённый / плавающий): **Главная · Медиатека · Поиск ·
Профиль**. Над таб-баром — мини-плеер. Полный плеер — `fullScreenCover` со свайпом вниз.

Таб-бар свой (не `TabView` со системной панелью) — иначе не получить три стиля и
сворачивание. Сворачивание (`photo_28 → 29`):
- каждый экран-список сообщает смещение прокрутки (`onScrollGeometryChange`, iOS 18) в
  `ChromeState`;
- прокрутка вниз больше 24 pt → `collapsed = true`; вверх больше 24 pt или у верхнего края →
  `false` (гистерезис, чтобы не дёргалось);
- развёрнуто: [мини-плеер на всю ширину] над [таб-бар из 4 иконок];
- свёрнуто: одна строка — [кнопка текущей вкладки ○] [сжатый мини-плеер] [кнопка поиска ○];
  тап по левой кнопке — разворачивает;
- переход — `matchedGeometryEffect` для обложки, названия и кнопки плей, пружина 0,35 с.

### 4.5а. Публичный сайт и профиль

`site/` — статический сайт на GitHub Pages (`sonar.folzy.ru`): главная (что такое Sonar,
кнопка «Скачать IPA» на последний релиз) и `/@username` — страница профиля. Это один
`index.html` + JS: берёт username из пути (404.html-трюк GitHub Pages), запрашивает
`GET <API>/public/users/{username}` (CORS разрешён только для этого домена) и рисует
аватар, имя, @username, #номер, дату регистрации и кнопку «Открыть в Sonar»
(`sonar://user/{username}`). Ничего приватного эндпоинт не отдаёт.

### 4.5б. Свой фон

Выбор из галереи (`PhotosPicker`): картинка → ресайз до 2560 px, JPEG 85 %; видео → обрезка
до 10 с, `AVAssetExportSession` 720p HEVC, без звука. `POST /me/background` (multipart) →
`{id, kind, url}` → настройка `appearance.bg_image = id`. Отрисовка: `AVPlayerLooper` для
видео, поверх — размытие и затемнение из настроек. На сервере файлы в `data/backgrounds/`,
один на пользователя (новый заменяет старый).

### 4.6. Автообновление

Порт `ShadowSelfUpdate` (≈2400 строк): `UpdateChecker` (JSON) → `IPADownloader` →
`BundlePreparer` + zsign (переподпись P12 пользователя) → `InstallServer` на
`127.0.0.1:<port>` + `manifest.plist` → `SFSafariViewController` открывает
`itms-services://?action=download-manifest&url=...` → iOS ставит.
Отличия от Shadow: SwiftSignalKit → async/await, Bazel → SwiftPM, manifest — с нашего сервера
(`GET /updates/manifest.plist?ipa=...`) вместо `api.palera.in`.

- Бот подтверждает вход кнопкой с названием устройства и текстом «Если это не ты — не жми».

## 9. Windows — **первая платформа** (решение 2026-11-14)

### 9.1. Стек
- **Tauri 2**: логика на Rust, интерфейс — веб (WebView2), как у Dotify (он тоже Tauri:
  exe ~20 МБ, фронт вшит в exe). Выбор ради анимаций (3D-наклон настроек, стекло, перекраска
  под обложку). Цена — ~150–200 МБ RAM.
- Фронтенд: **Svelte 5 + TypeScript + Vite**, свои компоненты, иконки Tabler.
- Rust-крейты: `reqwest` (rustls), `tokio`, `serde`, `rusqlite` (локальная база),
  `keyring` (токены в Диспетчере учётных данных Windows), `souvlaki` (медиа-клавиши и
  системная плашка Windows), `discord-rich-presence`, `tauri-plugin-autostart`, трей Tauri,
  `tauri-plugin-updater` (автообновление из GitHub Releases).
- Флаги WebView2 (как у Dotify): autoplay без жеста, без троттлинга фоновых таймеров,
  GPU-растеризация; системные медиа-клавиши WebView отключены — их ведёт Rust.
- **Образец — Dotify** (приложение друга владельца, разрешено опираться): распакованный
  фронтенд лежит локально в `C:/Users/Folzy/dotify-work` (в репо не идёт). Его стек: Tauri +
  React 19 + Tailwind, Dexie (IndexedDB), `hls.js` + `<audio>`, локальный аудио-сервер Rust
  на `127.0.0.1:53080`, WebGL-фон текста, шрифты fontsource. Sonar остаётся на Svelte, но
  берёт оттуда вид, размеры, флаги WebView2 и приёмы: `hls.js` для HLS SoundCloud (W2),
  WebGL-фон текста (W4), шрифты fontsource (W5).

### 9.2. Аудио
- Играет **WebView** (`<audio>` + Web Audio): два элемента по очереди — бесшовность и
  кроссфейд; `GainNode` — нормализация; `AnalyserNode` — визуализатор; `setSinkId` — устройство вывода.
- **Локальный аудио-сервер Rust на `127.0.0.1:<порт>`** (приём Dotify): `/stream?ref=sc:123`
  → Rust берёт ссылку у SoundCloud/Яндекса, отдаёт поток с Range, на лету пишет в кэш,
  склеивает HLS SoundCloud. Интерфейс видит обычный URL — без CORS и протухших ссылок.
- `/cover?url=…&size=300` — локальный кэш и ресайз обложек (W5).
- Сделано в W2 (`src-tauri/src/stream.rs`): `/file?ref=` (файл с Range, на 403/410 — новая ссылка),
  `/hls?ref=` (m3u8, ссылки кусков и `EXT-X-MAP` переписаны на `/seg?u=…`), `/seg` — только CDN
  SoundCloud (`*.sndcdn.com`, `*.soundcloud.cloud` — с 2026 куски идут с
  `playback.media-streaming.soundcloud.cloud`). Вариант потока SC: AAC HLS с большим битрейтом →
  mp3 файлом → mp3 HLS; DRM (`*-encrypted-hls`) и Opus пропускаются. Без своих ключей SoundCloud клиент
  сам берёт публичный client_id со страницы soundcloud.com (как selfbot), при 401/403 — свежий: поиск и
  открытые треки работают сразу после установки. Яндекс — запросы с IP
  компьютера (вариант 3 из §3.7а), mp3 ≤ `audio.quality`.

### 9.3. Автономный режим → сервер → API
1. **Сейчас (до хостинга):** всё на компьютере — токены SC и Яндекса в `keyring`, лайки,
   плейлисты, история, статистика, настройки — в локальном SQLite
   (`%APPDATA%/com.folzy.sonar/sonar.db`). Тексты — lrclib → Genius (§3.7б).
2. **Сервер:** вход, локальные данные отправляются на сервер, дальше синхронизация (API.md).
3. **Своё API Sonar — цель владельца:** клиент Sonar становится его основным плеером, а
   selfbot и другие его сервисы берут данные **из API Sonar** (`/oauth/now` в формате Dotify,
   треки, лайки, статистика) — вместо Dotify. Поэтому уже в автономном режиме:
   - локальная база повторяет схему `DB.md` (те же таблицы и поля) — перенос на сервер без
     переделок;
   - клиент с первого дня пишет «сейчас играет» в формате `PlayerState` (API.md §5) и
     историю прослушиваний как `plays` — на сервере это сразу превращается в `/oauth/now`
     и статистику;
   - `/oauth/now` и ключ API — **первые эндпоинты сервера** после входа (ROADMAP этап 1).
   Код работы с сервисами (`src-tauri/src/providers/`) потом переносится в сервер по той же
   структуре или остаётся в клиенте, если сервер к Яндексу не пустят (§3.7а).

### 9.4. Окно
Без системной рамки, минимум 960×640. Раскладка, экраны, анимация настроек, мини-плеер,
полноэкранный плеер — `PLATFORMS.md`. Трей, автозапуск, экономия ресурсов — `SETTINGS.md`.
Оверлей, горячие клавиши, поиск по тексту, таймер сна, скачивание в файл — не делаем.
