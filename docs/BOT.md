# Sonar — Telegram-бот `@SonarMusicApp`

Спека бота по решению владельца 2026-11-15 (скрины бота Dotify — как образец вида).
Заменяет таблицу команд из TZ §4.15; тексты «как достать токены» остаются там.
Бот — часть сервера (`server/`, aiogram 3, тот же процесс и та же БД, SPEC §3).

## 0. Вид

- **Каждый экран — одно сообщение:** баннер-картинка сверху (тёмный градиент, иконка + слово:
  «Sonar» с логотипом, «Профиль», «Вход», «Регистрация», «Статистика», «Поддержка»), под ней
  текст, блоки-цитаты (`<blockquote>`) и inline-кнопки с иконками.
- **Навигация правит то же сообщение** (`edit_message_media` / `edit_message_caption`), новых
  сообщений не плодим. Кнопка «◀️ Назад» везде, где есть куда вернуться.
- Шаги ввода (логин, пароль, текст репорта) — короткие сообщения без баннера: заголовок жирным
  с иконкой и блок-цитата с подсказкой («Теперь введи **пароль**:»).
- Итог действия — «**Успешно!**» / «**Отправлено!**» + цитата с деталями (как на скринах 4 и 5).
- Логины, номера репортов и даты — моноширинным (`<code>`), чтобы копировались по тапу.
- Язык — русский (английский — потом, вместе с локализацией приложения). Обращение на «ты».
- Баннеры — JPEG 1280×640 в `server/sonar/bot/assets/` (`main`, `profile`, `login`, `register`,
  `stats`, `support`), рисует `server/tools/make_banners.py` (знак из `brand/logo.svg`, значки — свои
  фигуры). В Telegram загружаются один раз, дальше — по `file_id` (кэш в таблице `kv`).
- **Лог-группа** (`SONAR_LOG_CHAT_ID`, форум, как у LGU-бота и selfbot): бот сам создаёт темы «Sonar»
  (запуск, регистрации, входы, выходы, обращения, смена статуса сервисов) и «Sonar · Ошибки»; удалённая
  тема создаётся заново. Раз в сутки — бэкап `sonar.db` (zip) **только** в общую тему «Data»
  (`t.me/c/2276939424/32139`, `SONAR_DATA_THREAD_ID`). Сайт и туннель, которые ещё ни разу не
  отвечали, в `/status` — «не настроен» и шапку не портят. Владелец в логах — «DEV», без пинга.
- **Пока нет группы поддержки** (`SUPPORT_GROUP_ID` пуст), обращения приходят владельцу в личку бота:
  карточка с кнопками Принять / Отклонить / Закрыть и копии сообщений; ответ **реплаем** на копию уходит
  пользователю. С группой — темы, как в §2.10.

### Премиум-эмодзи (решение владельца 2026-11-15)

- Иконки в сообщениях бота — **премиум (кастомные) эмодзи**, как у Dotify: в HTML-разметке
  `<tg-emoji emoji-id="5463231918436823008">⏳</tg-emoji>`, внутри — обычный эмодзи на случай,
  если кастомный не покажется.
- **Порядок важен:** в сообщении эмодзи идут по порядку, и бот подставляет их по порядку. Пример
  макета владельца (экран заказа Dotify): «⏳ Минутку… / 🔗 Заказ / 🛒 Товар / 💵 Сумма / 🏛 Метод:
  Platega 💵» — 6 эмодзи, ID по порядку:
  `5463231918436823008` ⏳ · `5463345666350690422` 🔗 · `5210997770567062009` 🛒 ·
  `5208509635882947404` 💵 · `5211219901980643543` 🏛 · `5208509635882947404` 💵.
  Одинаковый ID — значит один и тот же премиум-эмодзи (купюра у «Суммы» и после «Platega»);
  разные значки (банк у «Метода») — разные ID.
- В коде — один словарь `server/sonar/bot/emoji.py`: для каждого экрана упорядоченный список
  `(обычный эмодзи, emoji_id)`; текст экрана пишется с метками `{e0}`, `{e1}`…, функция подставляет
  `<tg-emoji>` по порядку. Поменять эмодзи — поменять ID в одном месте.
- ID берутся ботом `@TgEmojis` (Get Emoji ID Bot): переслать ему сообщение-макет — он вернёт
  список ID по порядку. Владелец пришлёт макеты для каждого экрана Sonar.
- Боты сейчас могут слать премиум-эмодзи без ограничений (проверено владельцем 2026-11-15).
  Обычный эмодзи внутри `<tg-emoji>` — только запасной вариант на старых клиентах.

## 1. Команды

В меню бота (`setMyCommands`) — **только две**:

| Команда | Что делает |
|---|---|
| `/start` | Главное меню (§2.5), а если Telegram не привязан к аккаунту — экран входа (§2.1). С параметром `link_<code>` — быстрая ссылка (§3) |
| `/status` | Состояние Sonar (§4) |

Всё остальное (профиль, статистика, сервисы, ключ API, баг/идея) — **кнопками** из главного
меню. Админ-команды (TZ §4.16: `/user`, `/setlogin`, `/ban`, `/broadcast`…) работают только у
владельца и в меню не показываются.

## 2. Экраны

### 2.1. `/start` без аккаунта

Баннер «Sonar». Цитата: «Аккаунт не привязан к Sonar\nВойди или зарегистрируйся, чтобы продолжить».
Кнопки: **🔓 Войти** · **📝 Регистрация** (без «Баг / Идея» — поддержка только для вошедших, решение владельца 2026-11-15).

### 2.2. Вход логином и паролем

1. Баннер «Вход». «**Вход** 📥» + цитата «Введи свой **логин**:». Кнопки: **⚡ Быстрая ссылка** (§3) ·
   **✖️ Отмена**.
2. Пользователь пишет логин → «**Вход** 🔑» + цитата «Теперь введи **пароль**:».
   Логина нет → «Такого аккаунта нет» + кнопки «Попробовать снова» · «📝 Регистрация».
3. Пользователь пишет пароль → **бот сразу удаляет это сообщение** (пароль не остаётся в чате).
   - Неверный → «⌫ Неверный пароль» и снова ждёт пароль. Лимит — 5 попыток за 15 минут на
     логин и на Telegram-аккаунт (как вход в приложении, SPEC §3.4), дальше «Слишком много
     попыток, попробуй через 15 минут».
   - Верный → «**Успешно!** ✨» + цитата «Аккаунт `folzy` теперь привязан к Telegram». Через
     1,5 с — главное меню.
4. «Отмена» на любом шаге → «Ок, в другой раз 👋» и экран §2.1.

**Важно:** в приложении вход **всегда сначала логин + пароль**, даже если человек ни разу не был
в боте. Telegram потом только привязывается (§2.2 или §3) и даёт быстрый вход на новых устройствах.
Почты нет. **Google** — идея «было бы прикольно, в теории», не в плане (§8).

### 2.3. Регистрация

Баннер «Регистрация». Шаги как во входе: логин (3–24 символа, `a-z 0-9 _ .`, свободен ли —
проверяется сразу) → пароль (от 8 символов) → пароль ещё раз. Сообщения с паролями бот удаляет.
Итог — «**Успешно!** ✨ Аккаунт `login` создан и привязан к Telegram» + кнопка «⬇️ Скачать Sonar».
`@username` и отображаемое имя по умолчанию = логин (меняются в приложении).

### 2.4. Выход

Профиль → «🚪 Выйти» → «Ты уверен, что хочешь выйти? Придётся авторизоваться заново.»
Кнопки: **✅ Подтвердить** · **◀️ Назад**. Подтвердил — Telegram отвязан от аккаунта, экран §2.1.
Аккаунт без пароля (старый вход только через Telegram) отвязать нельзя — «Сначала задай пароль
в приложении».

### 2.5. Главное меню

Баннер «Sonar». «Привет, **<имя>**! 👤\n\nЧем я могу помочь?» Цитата: «Поддержка — кнопка
⚠️ Баг / Идея ниже».
Кнопки: **👤 Профиль** · **📊 Статистика** · **🎧 Сервисы** · **⚠️ Баг / Идея** · **⬇️ Скачать Sonar**
(ссылка на сайт).

### 2.6. Профиль

Баннер «Профиль». «👤 **Твой профиль**»
- Цитата «**Аккаунт**: Имя: Folzy · Логин: `@folzy` · `#104633` · с 14 ноября 2026».
- Цитата «**Сервисы**: SoundCloud ✅ · Яндекс Музыка ✅».
- Цитата «**Неделя**: 412 мин · 96 треков».

Кнопки (как у Dotify, без платежей — подписок у нас нет):
**🎁 Рефералка** · **🔗 Интеграция** (в одном ряду) · **🚪 Выйти** (§2.4) · **🧪 Версии** · **◀️ Назад**.
Профиль на сайте — ссылкой в тексте: `try-sonar.ru/@username`.

### 2.6а. Интеграция

Для selfbot и своих сервисов (раньше называлось «Ключ API»). Без баннера, как у Dotify:

```
🔗 Интеграция

Сейчас играет 🎧
┃ GET https://sonar-api.folzy.ru/oauth/now?token=...
┃ Текущий трек, обложка, тайминги

Профиль 👤
┃ GET https://sonar-api.folzy.ru/oauth/profile?token=...
┃ Никнейм и аватарка

🔑 Токен: (спойлер)
```

Кнопки (каждая в своём ряду, сверху вниз): **📋 Скопировать токен** (кнопка `copy_text` — копирует
сразу) · **🔄 Обновить токен** (подтверждение «Старый токен перестанет работать. Обновить?» [Да] [Назад]) ·
**🗑 Отозвать токен** (с подтверждением) · **◀️ Назад**. Токена нет — «Токена нет» и «✨ Создать токен».
**Токен виден всегда** (решение владельца 2026-11-15): /start → Профиль → Интеграция — и он в поле
спойлером. Поэтому сервер хранит его **зашифрованным** (Fernet, как токены сервисов) плюс хэш для
поиска при запросе (`api_keys`, DB.md), а не только хэш. `GET /oauth/profile` — §6.

**Один токен на бот, приложение и OBS** (решение владельца 2026-11-16, делается с сервером): токен
«Интеграции» — общий для аккаунта. Создал или обновил его в боте — клиенты подхватывают сами
(синк, `GET /me/integration`); нажал «↻ Новая ссылка» в приложении (Интеграции → OBS Studio) — бот
показывает уже новый; «🗑 Отозвать» в боте = «Выключить плашку» в приложении. Плашка OBS тогда
открывается и с сервера — `https://sonar-api.folzy.ru/obs?token=…` (та же страница, данные «сейчас
играет» с сервера), а локальная `127.0.0.1:53119/obs?token=…` принимает тот же токен. До сервера у
плашки свой локальный токен (`obs.token`, Windows `obs.rs`).

### 2.6б. Рефералка

```
🎁 Рефералка
```

### 2.6е. Версии на устройствах (с сервером, решение 2026-11-17)

- Каждое устройство при запуске сообщает серверу `device_id`, `platform`, `name`, `app_version` (API.md
  `/me/devices`). `device_id` неизменяемый: iPhone — UUID, сам создаётся и живёт в Keychain (переживает
  переустановку, как в Shadow); Windows — HWID машины; Android — то же, что iOS, в Keystore.
- **Несколько устройств одной платформы** (ПК + ноутбук, два iPhone) — у каждого свой `device_id`, поэтому
  версия видна по каждому отдельно: «Windows 10 (Folzy) — 0.1.42», «Windows 11 (Laptop) — 0.1.40».
- В боте «Версии» у вошедшего: кнопка платформы **подсвечена зелёным** (✅ в тексте кнопки), если хотя бы одно его
  устройство этой платформы отстаёт от актуальной версии; рядом — какое. Все актуальны — без подсветки.
  Нет устройства платформы — обычная кнопка.

### 2.6ж. Завершение сессий (с сервером, решение 2026-11-17)

- Профиль → Безопасность → Устройства (бот и приложения): список сессий с именем устройства, платформой,
  версией, последним входом; **Завершить** — выйти на том устройстве; **Завершить все, кроме этой**.

  подписью и временем, когда станет можно. Свою сессию («Выйти») — можно всегда.

### 2.10. Баг / Идея — обращения в поддержку

Как в магазине владельца (`TG store/project/services/support.py`): **одно обращение = одна тема
в группе-форуме поддержки** (`SUPPORT_GROUP_ID`), переписка идёт через бота в обе стороны.
Оформление — в стиле нашего бота (баннеры, цитаты, иконки), и кроме текста можно слать фото,
видео, файлы и голосовые.

**Шаги пользователя:**
1. Главное меню → «⚠️ Баг / Идея» → баннер «Sonar», «Баг или идея?» [**🐞 Баг**] [**💡 Идея**] [**◀️ Назад**].
2. Баг → «Где произошёл баг?», идея → «В какое приложение добавить?» — кнопки по системам
   (решение владельца 2026-11-15): [**Windows**] [**iOS**] [**Android · в разработке**] [**◀️ Назад**]
   с логотипами (`logo_windows`, `logo_apple`, `logo_android`). Callback `report_platform_windows` /
   `report_platform_ios`. **Android** пока не выбирается: кнопка приглушена, по нажатию — только
   всплывашка (`answerCallbackQuery(show_alert=True)`) «Android-версия Sonar в разработке», экран не меняется.
3. Баннер «Sonar»: «**Что случилось?**\nМожно приложить скриншот или видео.» (для идеи —
   «**Расскажи идею**\nМожно приложить картинку.») + [**✖️ Отмена**] → «Ок, в другой раз 👋».
4. Первое сообщение (текст, фото, видео, файл, голосовое — что угодно) **создаёт обращение**:
   - в группе поддержки появляется тема «`#053d4a74` · 🐞 Баг · Windows — Folzy (@folzy)» (идея —
     «💡 Идея · iOS»), в ней карточка (кто, логин, версия приложения и ОС, если известны,
     ссылка на профиль) и само сообщение;
   - пользователю: «**Отправлено!** ✨» + цитата «Обращение `#053d4a74` создано. Пиши сюда — всё
     уйдёт в поддержку.» + кнопка [**✖️ Закрыть обращение**].
5. **Каждое** следующее сообщение пользователя уходит в ту же тему, и бот коротко подтверждает,
   чтобы не казалось, что обращение закрылось само:
   - текст → «✉️ Отправлено»;
   - фото / видео / файл → «📎 Прикреплено» (альбом — одним «📎 Прикреплено: 3»).

   Подтверждения — короткими ответами на сообщение, без баннера. Пока обращение открыто, всё, что
   пишет пользователь (кроме `/start`, `/status` и кнопок меню), идёт в него.

**Сторона владельца (тема в группе):**
- Ответ в теме (текст или медиа) → пересылается пользователю: «💬 **Поддержка:**» + текст.
- Кнопки на карточке: **✅ Принять** · **❌ Отклонить** · **🔒 Закрыть** (и `/close` в теме).
  - Принять → пользователю «✨ Твой баг-репорт `#053d4a74` ✅ принят» (идея — «Твоя идея … принята»).
  - Отклонить → «… ❌ отклонён» (+ причина, если владелец перед этим ответил в теме).
  - Закрыть → «✅ Обращение `#053d4a74` закрыто. Если вопрос не решён — открой новое: ⚠️ Баг / Идея»,
    тема закрывается (`close_forum_topic`).
  - Позже для бага — «🛠 Исправлено в версии 0.2.0».
- Владелец может сам открыть обращение пользователю (`/ticket <логин>`), как
  `open_ticket_by_admin` в магазине.

**Правила:** у пользователя одно открытое обращение; новое — после закрытия старого. Владелец
может ограничить поддержку пользователю (`/block_support <логин> [причина]`) — тогда «Доступ к
обращениям ограничен». Переписка дублируется в базу (`support_messages`): тему могут удалить,
группу — пересоздать. Из приложения («О приложении» → «Сообщить о проблеме», с последними 500
строками лога) создаётся такое же обращение в той же группе.

### 2.11. Ссылка на трек из Яндекса / SoundCloud → в Sonar (решение владельца 2026-11-16)

Прислали трек из Яндекс Музыки или SoundCloud — кидаешь ссылку боту, бот отвечает ссылкой на этот трек в Sonar.
- Понимает: `music.yandex.ru|.com|.by|.kz/album/<a>/track/<t>`, `music.yandex.*/track/<t>`, `soundcloud.com/<user>/<slug>`,
  `on.soundcloud.com/<code>` (короткую раскрывает редиректом), `soundcloud.app.goo.gl/…`.
- Ответ: обложка + «**Название** — Артист» + кнопка **Открыть в Sonar** (`https://try-sonar.ru/t/<ref>`, `ref` —
  `ym:<id>` или `sc:<id>`; для SoundCloud id берёт сервер через `resolve`). Сайт сразу перекидывает в приложение
  `sonar://track/<ref>`; приложения нет — показывает карточку трека и кнопку «Скачать Sonar».
- Приложение по `sonar://track/<ref>` открывает **страницу трека** (как альбом, но один трек: обложка, название,
  артист, кнопки «Слушать», лайк, «В плейлист», похожие ниже) с подписью «Открыто по ссылке».
- Нужно: сервер (метаданные и `resolve` SoundCloud), сайт `/t/<ref>`, схема `sonar://` в Windows (Tauri deep-link)
  и iOS. Делается вместе с этапом 2 ROADMAP.

### 2.12а. `/dotify` — перенос Любимых из Dotify (скрытая, решение владельца 2026-11-25)

В меню команды нет. Только вошедшим (Telegram привязан к аккаунту): `/dotify` → «Пришли файл .dotifyplaylist» →
бот разбирает файл и показывает, сколько добавит, сколько уже в Любимых, сколько снято вручную (их не возвращает)
и сколько не SoundCloud / Яндекс (пропуск) → «Добавить N» / «Отмена». До «Добавить» ничего не пишется; файл не
хранится (на «Добавить» бот скачивает его ещё раз). Лайки — строки синка `like` (с `added_at` из файла и карточкой
трека), устройства получают их обычным `pull` (API.md §6). Код — `server/sonar/dotify.py`, разбор полей —
как у `windows/scripts/import-dotify-playlist.py`; повтор того же файла ничего не удваивает. Файл до 5 МБ, до 20 000 треков.

### 2.12б. `/update` — обновление сервера по частям (скрытая, только владелец, 2026-11-26)

В меню команды нет; чужим бот не отвечает. Схема как у `/update` в lengubot, без панели хостинга и без рестарта
контейнера. `/update` → «Проверяю GitHub…» → экран: по каждой части что стоит и что на GitHub.
- **Сервер** (бот + API + админка — один процесс, поэтому только вместе; плюс зависимости и сам `sync.py`): «Только
  сервер» — бот останавливает опрос, процесс перезапускается через `os.execv(sync.py)` (тот же PID, секунд 20–40),
  сообщение «Обновляю…» после старта правится на итог («обновлён a → b» / «версия не та»). Кнопка есть, только если
  в **`server/`** есть правки: коммиты про iOS, Windows, сайт и доки её не вызывают, и `sync.py` на старте для них
  архив репо больше не качает (compare API). Показаны коммиты, трогавшие `server/`.
- **Сайт** (`site-latest`): «Только сайт» — подмена на лету, без перезапуска.
- «Обновить всё» — обе части; «Проверить снова»; «Перезапустить» (с подтверждением) — без обновления, подхватить `.env`.
Код — `server/sonar/updater.py`, `server/deploy/sync.py` (`status`, `update_site`, `SONAR_SYNC_SKIP`), `bot/handlers.py`
`cmd_update` / `update_button` / `announce_update`. То же самое — в админке, страница «Сервер» (ADMIN.md §0).

### 2.12в. `/admin` — команды владельца (скрытая, только владелец, 2026-11-26)

В меню команды нет, чужим бот не отвечает. Экран: «Открыть админку» (ссылка на `<public_url>/admin/`), «Сбросить пароль
админки», «Обновление сервера» (§2.12б), «Статус».
- **Сброс пароля** (забыл заводской; в консоли панели Velt нет shell для `python -m sonar.admin passwd`): подтверждение →
  `AdminAuth.reset_password()` — новый случайный пароль для `folzy` (старый не работает, сессии админки закрыты, при входе сразу
  форма смены — `must_change`). Бот показывает логин и пароль, **сообщение удаляется через 2 мин**; в журнал админки пишется
  `reset_admin_password` (`telegram:<id>`). Безопасность держится на Telegram ID владельца (`SONAR_OWNER_TG_ID`).

### 2.12г. Блокировки: `/who` `/ban` `/unban` `/rban` `/runban` `/banned` (скрытые, только владелец, 2026-11-26)

В меню команд нет; `/admin` даёт кнопки «Заблокированные» и «Как банить». «Кто» — логин, `@username`, `#номер` или
Telegram ID; срок — `30м`, `2ч`, `3д`, `1н`, `7 дней` или `навсегда` (не указан — **навсегда**), дальше — причина.
- `/ban кто [срок] [причина]` — бан аккаунта: все устройства на следующем запросе получают `403 account_banned` (API.md §1)
  и выходят с экраном «Учётная запись заблокирована» (срок, причина); в боте любое сообщение и любая кнопка заблокированного
  отвечают тем же (`bot/moderation.py` `ban_gate`; владельца не выкинуть и не заблокировать). Временный бан снимается сам.
- `/rban кто [срок] [причина]` — закрыть **обращения «Баг / Идея»** (спам в поддержку): кнопка, начатый черновик и сообщения
  в уже открытое обращение отвечают «Обращения отключены» со сроком; всё остальное работает. Блок — по Telegram ID
  (`support_blocks`): можно и тому, у кого нет аккаунта (`/rban 12345`).
- `/who кто` — карточка со статусом обоих блоков и кнопками «Бан 1 дн / 7 дн / навсегда», «Разбанить», «Обращения · …».
- `/banned` — кто заблокирован и кому закрыты обращения. То же есть в веб-админке (карточка пользователя: срок бана, блок
  обращений). Всё пишется в журнал (`ban`, `unban`, `report_block`, `report_unblock`, `ban_expired`).

### Вход нового устройства и привязка Telegram из приложения (2026-11-25)

Приложение даёт ссылку в бота: `?start=link_<код>` — вход нового устройства (как быстрая ссылка, только наоборот):
у кого Telegram привязан к аккаунту, видит «⚠️ Авторизация в аккаунт … для: iPhone 15 Pro · Sonar 1.0», кнопка
«Разрешить» появляется через 3 секунды, «Отклонить» — сразу; Telegram не привязан — «войди логином в приложении».
`?start=tg_<код>` — вошедший в приложении привязывает этот Telegram: «Привязать» / «Отмена». Коды одноразовые,
5 минут, друг друга не заменяют. Разрешили в приложении быструю ссылку из бота — бот пишет «Успешно! Аккаунт … привязан».

## 3. Быстрая ссылка и подтверждение входа

Вход без пароля для **нового** устройства или для бота. Одна схема на всё:

1. Новое место (бот на шаге входа, или приложение на новом ПК/iPhone — кнопка «Войти через
   другое устройство») создаёт **запрос входа**: `POST /auth/link` → `{code, url, expires_at}`.
   Ссылка живёт **5 минут** и одноразовая.
   - В боте: сообщение «⚡ Быстрая ссылка» + цитата «Открой на устройстве, где ты уже вошёл
     в Sonar. Действует до 13:15» + кнопка **Открыть в Sonar** со своим знаком (`logo_sonar`, `brand/emoji`) (`sonar://auth/<code>`,
     запасной адрес `https://try-sonar.ru/auth/<code>` открывает приложение).
     Истекла — сообщение правится: «Ссылка истекла» + «Новая ссылка».
   - В приложении: ссылка + QR-код + «Скопировать».
2. Ссылку открывают **там, где уже вошли** (приложение ПК или iPhone). Приложение показывает
   **окно подтверждения** (ниже).
3. «Разрешить» → `POST /auth/link/{code}/approve` → новое место получает сессию
   (`GET /auth/link/{code}/poll`), бот пишет «**Успешно!** ✨ Аккаунт `folzy` теперь привязан к
   Telegram». «Отклонить» → запрос закрыт, новое место видит «Вход отклонён».

### Окно подтверждения (приложение, ПК и iOS)

Защита от «вот ссылка, послушай трек» — чтобы никто не получил доступ к чужому аккаунту:

- **По центру, примерно на пол-экрана**, фон приложения затемнён и размыт. Закрыть кликом
  мимо нельзя — только кнопками.
- Сверху **красным**: «⚠️ Авторизация в аккаунт».
- Текст: «Разрешить доступ к аккаунту **@folzy** для: **Telegram @cocainemodel** (бот Sonar)» —
  или «**Windows · Sonar 0.1.0**», «**iPhone 15 Pro · Sonar 1.0**». Ниже: когда создан запрос
  и сколько осталось («ещё 4:12»).
- Предупреждение мелко: «Если тебе прислали эту ссылку и просят нажать — не разрешай. Так
  получают доступ к чужим аккаунтам.»
- Кнопки:
  - **Разрешить** — чёрный текст на белом фоне. **Первые 3 секунды неактивна**: на ней
    обратный отсчёт «Разрешить · 3» → «2» → «1», фон — светлый, но не белый (≈ 60 % белого),
    по отсчёту плавно заливается до **полностью белого** и становится активной.
  - **Отклонить** — нейтральная (прозрачная с рамкой), активна сразу.
- Анимации: окно появляется из масштаба 0.96 с прозрачностью, заливка кнопки — слева направо
  за 3 с, исчезает быстрее, чем появилось. «Меньше движения» — только прозрачность и цифры.
- Истёк срок, пока окно открыто, — кнопки гаснут, текст «Ссылка истекла».

## 4. `/status`

Тот же источник, что страница статуса и `GET /status` (SPEC §3.11).

**Для всех:**

```
🟢 Все системы работают штатно

🎧 Слушают онлайн: 3
👤 Слушателей за 24 часа: 7
👥 Пользователей: 12
⏱️ Аптайм: 99.98%

Инфраструктура:
└ 🗄 Основной: ✅ Работает · 42 мс

Музыкальные платформы:
├ SoundCloud: ✅
├ Яндекс Музыка: ✅
├ YouTube Music: ✅
├ VK Музыка: ✅
├ Spotify: ✅
└ Apple Music: ✅
```

«Слушателей за 24 часа» — разные аккаунты, которые за последние 24 часа что-то слушали (`plays` или
играющий `player_state`), один аккаунт — один слушатель. Мс «Основного» видны всем: ответ сервера
снаружи через туннель (`/health`), пока туннеля нет — запрос к БД. YouTube Music, VK Музыка, Spotify и
Apple Music Sonar ещё не подключил — пункт значит «сервер до них достаёт» и в шапку не идёт
(решение владельца 2026-11-18).

Хранилище и причины сбоев остальным не видны (решение владельца 2026-11-25).

**Владельцу** (`SONAR_OWNER_TG_ID`) — то же плюс служебные пункты и задержки. С 2026-11-25 у каждого ⚠️ / ❌ —
причина: `HTTP 403 — капча Cloudflare или запрет для серверов`, `HTTP 429 — лимит запросов`, `не ответил за 5 с`,
`нет соединения (DNS или сеть)`, `медленно: 2.9 с`. Хранилище — свои файлы против лимита тарифа, а не диск хоста:
`занято 0.6 ГБ из 2.0 ГБ, свободно 1.4 ГБ · база 12 МБ` (лимит — `SONAR_DISK_QUOTA_MB`, по умолчанию 2048; обход
папки — раз в 30 минут; ⚠️ — свободно меньше 100 МБ, ❌ — меньше 25 МБ):

```
Инфраструктура:
├ 🗄 Основной: ✅ Работает · 12 мс
├ 🎵 Медиа: ✅ Работает · 340 мс      — ссылки на поток SoundCloud и Яндекса выдаются
├ 🔀 Прокси: ✅ Работает · 95 мс       — Cloudflare Tunnel: API отвечает снаружи
├ 🤖 Бот: ✅ Работает
├ 🌐 Сайт: ✅ Работает
└ 📦 Хранилище: ✅ Работает · 1.2 ГБ свободно

Музыкальные платформы:
├ SoundCloud: ✅
└ Яндекс Музыка: ⚠️ 2.9 с

Тексты и прочее:
├ lrclib: ✅ · Genius: ✅
└ Telegram: ✅
```

- Шапка: 🟢 «Все системы работают штатно» · 🟡 «Некоторые сервисы работают с перебоями» ·
  🔴 «Сбой: <что>».
- **Слушают онлайн** — пользователи, у которых `player_state.is_playing` и heartbeat < 90 с
  (SPEC §3.9). **Пользователей** — всего аккаунтов (без забаненных).
- **Платформы** — только те, что есть в Sonar: сейчас **SoundCloud и Яндекс Музыка**. Владелец
  планирует до **5 сервисов** — новые (Spotify, YouTube, VK…) появляются в списке, когда их
  подключат в Sonar; заранее не показываем.
- Кнопки: **🔄 Обновить** (правит то же сообщение) · **🌐 Страница статуса**
  (`try-sonar.ru/status`).

## 5. Безопасность

- Сообщения с паролями бот удаляет сразу; в логах сервера паролей нет.
- Пароли — argon2id, сессии — только хэш (SPEC §3.4). Лимиты входа — общие с приложением.
- Быстрая ссылка: 5 минут, одноразовая, 32 случайных байта; подтверждение — только в
  приложении, где уже вошли, с названием устройства и задержкой 3 с.
- Токены сервисов бот не принимает (§2.8).
- Админ-кнопки (принять/отклонить репорт) работают только у `SONAR_OWNER_TG_ID`.

## 6. Сервер: API и данные

API (дополняет API.md §1):

| Метод | Путь | Тело → ответ |
|---|---|---|
| POST | `/auth/link` (без авт.) | `{device}` или `{telegram: {id, username}}` (из бота) → `{code, url, expires_at}` |
| GET | `/auth/link/{code}/poll` (без авт.) | → `{status: pending\|approved\|rejected\|expired, session?, user?}` |
| GET | `/auth/link/{code}` | (вошедший) → `{for: {kind: telegram\|device, name}, created_at, expires_at}` — для окна подтверждения |
| POST | `/auth/link/{code}/approve` · `/reject` | (вошедший) → `204` |
| POST | `/reports` | `{kind: bug\|idea, platform: windows\|ios\|android, text, app_version?, os?, log?}` + файлы → `{id: "053d4a74"}` — обращение и тема (§2.10) |
| GET | `/oauth/profile?token=` | → `{username, display_name, avatar_url}` (§2.6а) |

Таблицы (дополняют DB.md):

```sql
CREATE TABLE auth_links (
  code_hash   TEXT PRIMARY KEY,     -- SHA-256 кода из ссылки
  for_kind    TEXT NOT NULL,        -- telegram | device
  for_json    TEXT NOT NULL,        -- {id, username} или Device
  user_id     TEXT REFERENCES users(id),   -- кто разрешил
  status      TEXT NOT NULL,        -- pending | approved | rejected | expired
  created_at  INTEGER NOT NULL,
  expires_at  INTEGER NOT NULL      -- +5 мин
);
CREATE TABLE tickets (            -- обращение = тема в группе поддержки
  id          TEXT PRIMARY KEY,     -- 8 hex, «#053d4a74»
  user_id     TEXT REFERENCES users(id),
  tg_id       INTEGER NOT NULL,
  kind        TEXT NOT NULL,        -- bug | idea
  platform    TEXT NOT NULL,        -- windows | ios (android — когда появится)
  topic_id    INTEGER,              -- message_thread_id темы в SUPPORT_GROUP_ID
  status      TEXT NOT NULL,        -- open | accepted | rejected | closed | fixed
  app_version TEXT, os TEXT,
  created_at  INTEGER NOT NULL,
  closed_at   INTEGER
);
CREATE TABLE support_messages (   -- копия переписки
  id          INTEGER PRIMARY KEY,
  ticket_id   TEXT NOT NULL REFERENCES tickets(id) ON DELETE CASCADE,
  author      TEXT NOT NULL,        -- user | admin
  text        TEXT,
  file_id     TEXT, file_kind TEXT, -- photo | video | document | voice
  created_at  INTEGER NOT NULL
);
CREATE TABLE support_blocks (tg_id INTEGER PRIMARY KEY, reason TEXT, until INTEGER);
-- users: + referral_code TEXT UNIQUE, + referred_by TEXT REFERENCES users(id)
```

Состояния шагов (ждём логин / пароль / текст репорта) — aiogram FSM в памяти; перезапуск
сервера просто сбрасывает незаконченный шаг.

## 7. Что делать по порядку (когда будет сервер)

1. Баннеры (`make_banners.py`) — можно **уже сейчас**, без сервера.
2. Бот: `/start`, вход логином и паролем, регистрация, главное меню, профиль (этап 1 ROADMAP,
   вместе с аккаунтами).
3. `/status` — вместе со страницей статуса (шаг 7 этапа 1).
4. Быстрая ссылка + окно подтверждения в Windows-клиенте (оно же потом на iOS).
5. Обращения (темы в группе поддержки `SUPPORT_GROUP_ID`); статистика, сервисы, интеграция,
   рефералка, версии — этап 2.
