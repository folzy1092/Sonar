# Sonar — план

Честная оценка: **сервер + iOS MVP ≈ 2–3 недели** плотной работы. Windows — отдельно,
ещё 2–3 недели. Ниже — порядок, в котором каждый шаг можно проверить руками.

Старт — **после покупки сервера (суббота)**, чтобы ничего не перестраивать. До этого —
только теория.

## Этап 0. Подготовка (делает владелец)

- [ ] Velt → Контейнеры → Python: 512 МБ, 10 % vCPU, **2 ГБ** диска, 1 порт, 0 MySQL.
      Узнать страну сервера.
- [ ] DNS folzy.ru перенести на Cloudflare (Free), запись GitHub Pages сохранить →
      Zero Trust → Tunnels → туннель `sonar-api.folzy.ru → http://localhost:<порт>`, токен
      туннеля → env `CF_TUNNEL_TOKEN`.
- [ ] PR в `is-a-dev/register`: `domains/sonar.folzy.json` → `folzy1092.github.io`.
- [ ] Бот в @BotFather, токен → `SONAR_BOT_TOKEN`; бот — админ лог-группы (для тем «Tests»).
- [ ] Ключи Last.fm API (last.fm/api/account/create).
- [ ] Секреты GitHub Actions: пока не нужны (сборка без подписи).
- [ ] Иконка приложения (1024×1024).

## Этап 1. Сервер: каркас (дни 1–3)

0. **Сначала проверка сервисов** (`server/tools/check_*.py`, токены владельца в `.env`):
   поток SC; доступ к Яндексу **с сервера Velt и с ПК владельца** (поиск, трек,
   download-info, похожие), с правильными заголовками и без спешки. По итогам — вариант из
   SPEC §3.7а и правка документов.
1. `server/` по `MAP.md`, `python -m sonar` поднимает FastAPI + бота.
2. БД и миграции по `DB.md`.
3. Регистрация, вход, сессии, устройства, вход и привязка через Telegram.
4. Тесты на всё это. CI `server.yml`.
5. Деплой на Velt + туннель. **Проверка:** `curl <API>/health`.
6. `site/` на GitHub Pages: главная + страница профиля.

## Этап 2. Сервер: музыка (дни 4–6)

1. Провайдеры SoundCloud и Яндекс: подключение, поиск, трек, поток, related, фантомные
   плейлисты, импорт.
2. Лайки, плейлисты, синк (`pull`/`push`/`snapshot`/`replace`).
3. `player/state`, `plays`, `/oauth/now`. **Проверка:** selfbot `/get` на новый адрес.
4. Своя волна, главная, тексты, Last.fm,
   уведомления и `/broadcast`, аватар и свой фон.

## Этап 3. iOS: каркас и плеер (дни 7–11)

1. `ios/project.yml`, workflow `ios.yml` → IPA в Releases. **Проверка:** ставится через ESign.
2. `APIClient`, вход/регистрация/Telegram, Keychain.
3. `PlaybackEngine` + `QueueManager` + Now Playing, фон. **Проверка:** играет трек SC и Яндекса,
   экран блокировки работает, переход без паузы.
4. Мини-плеер, полный плеер, очередь.
5. `ThemeStore` + цвет из обложки.

## Этап 4. iOS: экраны (дни 12–16)

1. Главная (волна, подборки, недавнее), поиск.
2. Медиатека, Любимые, плейлисты, импорт из сервисов.
3. Профиль + меню настроек + все экраны настроек из `SETTINGS.md` (iOS-часть).
4. Жесты. Статистика. Текст песни. Кэш и скачивание.
5. Синхронизация в фоне + офлайн-очередь операций.

## Этап 5. iOS: автообновление и полировка (дни 17–19)

1. Порт `ShadowSelfUpdate` → `Update/`, `updates/update.json`, экран обновления.
2. Английская локализация.
3. Прогон с друзьями, правки. Релиз **1.0.0**.

## Этап 6. Windows (после 1.0.0)

Rust + Slint (или Tauri), настройки из `SETTINGS.md` (разделы PC), Discord RPC, трей,
мини-плеер, оверлей, OBS-плашка.

## Потом

Профили пользователей и друзья, приватность, «Итоги месяца», настройки волны Яндекса,
админка в вебе.
