## 1. Обложки-коллажи без повторов (ПК и iPhone)

**Видно:** в плитках из 4 обложек («Для тебя» → «Новое для тебя», свои плейлисты) одна и та же обложка
стоит 2–3 раза: берутся первые 4 трека, а они часто с одного альбома.

**Сделать:** общая функция «4 разные обложки» на обеих платформах:
1. Идём по трекам списка **не только с начала**: сначала первые ~30, если разных меньше 4 — дальше по всему списку.
2. Обложка считается повтором, если совпадает любое из:
   - ref альбома (`track.album.ref`);
   - адрес после нормализации: без размера (`-t500x500`, `-large`, `-t300x300` у SoundCloud; `%%` / `/400x400`
     у Яндекса; `=w544-h544` и подобное у YouTube; `?…`) и без схемы;
   - для треков без альбома — исполнитель + адрес.
3. Разных обложек 4 и больше — сетка 2×2 из разных; 2–3 — не сетка, а одна (первая) обложка во всю плитку
   (сетка с повтором выглядит как баг); 1 — одна; 0 — значок.
4. Порядок стабильный (тот же список → те же обложки), не случайный на каждое открытие.

Сравнение картинок по пикселям (perceptual hash) — **не делаем** сейчас: дорого, нужен только если после
пунктов 2–3 повторы всё ещё видны. Записать как «потом».

**Где:** ПК — `windows/src/lib/home-mixes.ts` (подборки), коллажи своих плейлистов (`components/Tile.svelte`,
где собираются `covers`), вынести в `lib/covers.ts` + тест; iPhone — `PlaylistCollage`
(`Features/Library/SonarPlaylistViews.swift`), `SonarPlaylist.covers`, подборки Главной; логику — в
`Core/Library/Covers.swift` + XCTest.

**Готово, когда:** «Новое для тебя» и плейлист из 10 треков одного альбома + 3 других показывают 4 разные
обложки или одну, но не повтор.

## 2. Вход в YouTube Music на ПК — ошибка «password encoded as UTF-16 is longer than 2560 chars»

**Почему (проверено):** входы лежат в Диспетчере учётных данных Windows (`secrets.rs`, crate `keyring`). У
одной записи предел — 2560 байт. Cookie music.youtube.com после входа длиннее, запись падает.

**Сделать:** большие секреты — **по частям**: `secrets::save` режет JSON на куски ≤ 1200 символов
(UTF-16 → ≤ 2400 байт) в записи `<name>`, `<name>#1`, `<name>#2`…, в первой — число частей; `load` склеивает;
`delete` стирает все части. Старые записи в одну часть читаются как раньше. Тест на 10 КБ.
Не класть cookie в файл или SQLite открытым текстом.

**Где:** `windows/src-tauri/src/secrets.rs`. iPhone — Keychain такого предела не имеет, не трогать.

## 3. Spotify на ПК — «ключ веб-плеера устарел»

**Почему (проверено):** вход Spotify подписывается TOTP веб-плеера; шифр вшит в сборку (`DEFAULT_TOTP` в
`providers/spotify.rs`), Spotify его сменил.

**Сделать:**
1. Сейчас — обновить шифр в сборке (взять актуальную версию из публичного источника, где его поддерживают
   открытые клиенты; лицензию источника проверить — копируем только значение, не код).
2. Чтобы не ждать обновления Sonar: шифр читается из `updates/spotify-totp.json` в репо (raw.githubusercontent,
   как `ios-update.json`) при запуске и при ошибке `TOTP_STALE`, вшитый — запасной. С сервером — из `GET /config`.
3. Ошибка в окне — понятная: «Spotify сменил защиту — Sonar подтянет новый ключ сам, попробуй через минуту».

**Где:** `windows/src-tauri/src/providers/spotify.rs`, iPhone — `Core/Providers/SpotifyCore.swift` (тот же шифр).

## 4. Автозапуск на ПК не работает

**Почему (проверено):** по умолчанию `system.autostart: true` (`lib/settings.svelte.ts`), но запись в реестр
(`HKCU…\Run`) делается **только при переключении** тумблера (`General.svelte` → `set_autostart`). После чистой
установки тумблер показывает реальное состояние «выкл», а настройка считается «вкл» — записи нет.

**Сделать:** при запуске сверить: настройка `system.autostart` ≠ состояние реестра → привести реестр к
настройке (один раз за запуск, без окна). Установщик NSIS: на странице «Ярлыки» — галочка «Запускать вместе
с Windows» (по умолчанию вкл), она же пишет настройку. Проверить, что запись в реестре ведёт на exe из
папки установки и с `--autostart` (старт в трее, без окна — это ожидаемо, сказать в подсказке тумблера:
«Sonar запустится в трее»).

**Где:** `windows/src-tauri/src/lib.rs` (setup), `commands.rs` `set_autostart`, `installer.nsi`.

## 5. Повтор и перемешивание — состояния еле различимы (ПК и iPhone)

**Видно:** «повтор выкл» и «повтор всё» отличаются едва заметной подсветкой; так же «перемешать».

**Сделать:** три состояния, различимые без присматривания:
- выкл — значок цвета `--text-secondary`, без фона;
- повтор всего / перемешивание — значок **акцентного цвета** + точка-индикатор под ним (4 px) + лёгкая
  подложка-кружок акцента 15 %;
- повтор одного — то же + цифра «1» в значке (уже есть) — проверить, что видна.
Переход между состояниями — анимация (масштаб 0.9 → 1, цвет плавно). «Меньше движения» — только цвет.
Подсказка при наведении (ПК) и accessibilityValue (iPhone): «Повтор: выкл / всё / один трек».

**Где:** ПК — кнопки плеера (`components/sonar-icons.ts`, нижняя панель, полноэкранный плеер, мини-окно);
iPhone — `FullPlayerView` `controls`, мини-плеер.

## 7. Перезаливы: «артист - трек» в названии + панель в админке

**Пример:** `cowboyclicker - doesnt matter (prod. gloro)` · исполнитель `Kleyy` (тот, кто перезалил). Genius и

**Как в selfbot (взять логику, не код):** `folzy-selfbot/title_split.py` — разбор перезаливов (только тире с

текста»** в админке (`admin_nolyrics.py`: сводка за сутки/неделю с перепроверкой, «Игнорировать»).

**Сейчас в Sonar:** только одна простая пара (`reupload_variant` в `lyrics/mod.rs`, `TrackText.reuploadVariant`

**Сделать:**

   - **игнор**: треки, где текста точно нет (инструменталы) — не искать и не показывать в «без текста».

## 8. Токен SoundCloud слетает на iPhone (401)

**Почему (вероятно, проверить):** при входе iPhone берёт **публичный client_id** со страницы soundcloud.com
(`SoundCloud.publicClientId()`) и сохраняет его вместе с токеном навсегда. SoundCloud меняет этот client_id
время от времени — старый начинает отвечать 401, и это выглядит как «слетел токен». Сам `oauth_token` из
cookie, по опыту, живёт долго, но точной документации нет — проверить.

**Сделать:**
1. На 401: сначала заново взять публичный client_id и повторить запрос; помогло — сохранить новый id.
2. Не помогло — тихо обновить вход: окно входа SoundCloud хранит cookie в **постоянном** хранилище своего
   WebView (сейчас — временное), невидимый WebView открывает soundcloud.com и забирает свежий
   `oauth_token`. Получилось — молча продолжить; нет — одна плашка «Войди в SoundCloud заново» с кнопкой.
3. Журнал: каждое обновление client_id / токена — строка в журнале сбоев (без значений), чтобы понять, что
   именно протухает.
4. С сервером: входы синкаются (`GET /services/credentials`), обновлённый токен с любого устройства уходит на
   сервер — остальные получают его при синке.

**Где:** `ios/Sonar/Core/Providers/SoundCloud.swift`, `MusicCore.swift` (вход SC), `Features/Settings/CookieLoginSheet.swift`.
ПК — проверить, есть ли то же самое (обновление client_id в `providers/soundcloud.rs`), и сделать так же.
