# Задание: сервер на Velt и клиенты на нём (2026-11-25)

Сервер куплен и уже крутится. Задача — довести его API до того, чтобы ПК, iPhone, сайт и селфбот работали через
него, а сборки и обновления раздавались с него же. Делать по этапам, каждый — отдельными коммитами в `main`, с
тестами. Перед началом прочитать `CLAUDE.md` (тон, git, i18n, анимации, офлайн), `docs/HANDOFF.md`, `docs/API.md`,
`docs/DB.md`, `docs/ADMIN.md`, `docs/BOT.md`.

## 0. Что уже есть (не переделывать)

**Хостинг.** Velt, Pterodactyl, Python 3.13, 512 МБ, 25 % vCPU, 2 ГБ, один порт (5006). Домен `try-sonar.ru`
(A-записи `@` и `www` на reg.ru) к порту привязал хостер, HTTPS — его прокси. Cloudflare нет и не нужен.
IP контейнера в репо не писать (репо публичное) — только «порт из панели».

**Запуск.** В контейнере только `sync.py` и `.env`. Стартовая команда — `python sync.py` (`server/deploy/sync.py`):
при новом коммите в `main` скачивает архив, берёт `server/` → `app/`, ставит `requirements-run.txt` в `.venv`,
запускает `python -m sonar`. База — `data/sonar.db` рядом, обновление её не трогает. Новый код подхватывается
**только при рестарте**, рестарт делает владелец из панели (агент доступа к панели не имеет) — в конце каждого
этапа писать владельцу «перезапусти сервер» в уведомлении. `GITHUB_TOKEN` в `.env` — если репо станет приватным
(ROADMAP «Выпуск: хостинг и закрытие репо»), `sync.py` его уже умеет.

**Сервер (`server/sonar`).** Один процесс: бот aiogram (polling) + FastAPI/uvicorn на `PORT`. Есть: аккаунты
(`accounts.py`: регистрация, вход, Telegram, argon2, токены сервисов шифрует Fernet), таблицы `users`, `sessions`,
`plays`, `player_state`, `api_keys`, `auth_links`, `events`, `subscriptions` и др. (`db.py`), админка `/admin`
(`admin/`), `GET /health`, `GET /config`, `POST /events`, статус-проверки (`status.py`), лог-группа, бэкап базы.
IP клиента за прокси — `admin/web.py` `_ip` (заголовкам верим только от `SONAR_TRUSTED_PROXIES`); в API брать оттуда же.

**Клиенты.**
- ПК: синк готов целиком — `store/sync.rs` (что слать), `sync.rs` (HTTP-транспорт, фон раз в 2 мин, `MemoryServer`
  — образец логики сервера), сторона синка `sync_state.sync_target` (`server` / `lan` / `offline`), хаб по Wi‑Fi
  `store/hub.rs` + `remote/sync_hub.rs` (это тот же протокол §6 — его логику и тесты переиспользовать на сервере).
  Экрана входа в аккаунт Sonar на ПК **нет** — профиль локальный (`profile.*`).
- iPhone: `Core/Account/` (вход, регистрация, Telegram, устройства по API.md, `APIClient`), `Core/Sync/`
  (`SyncEngine`, `MemorySyncServer`) — всё за флагом `server.enabled` (выкл.) и адресом `server.url` / Info.plist.
- Сайт `site/` (Astro): сейчас собирается и уходит на GitHub Pages (`site.yml`). Профиль `/@username` и `/status` —
  заглушки, ждут API.

## 1. Решения для этого задания (2026-11-25)

Владелец решил: всё на Velt, сборки выпускает сам, автообновление — с сайта. Агент решил (технические, можно
пересмотреть с объяснением): префикс `/api`, сервер сам скачивает сборки из релизов CI, архив сайта через релиз.

- **Всё на одном сервере:** сайт, API, админка, файлы сборок. GitHub Pages и GitHub Releases как источник для
  пользователей — убрать (CI продолжает собирать, но не публикует для пользователей).
- **API — под префиксом `/api`:** `<API>` = `https://try-sonar.ru/api`. Сайт живёт в корне, и пути пересеклись бы
  (`/status` — и страница, и метод; `/@username`). Админка — `/admin`. Пути внутри API — как в `docs/API.md`
  (`/api/auth/login`, `/api/sync/pull`…). Поправить «База:» в API.md, SPEC §3.2 и `SONAR_PUBLIC_URL`.
  Уже существующие `/health`, `/config`, `/events` перенести под `/api`, старые оставить алиасами на время.
- **Сборки выпускает владелец сам** (2026-11-25): CI собирает, владелец проверяет и в админке жмёт «Выпустить»
  как **релиз** или **бета** с описанием. Пока не выпустил — пользователи сборку не видят. Автообновление ПК и
  iPhone смотрит на сайт, а не на GitHub.
- **Сервер не трогает аудио** и не ходит в сервисы от имени пользователей (играет устройство со своего IP).
  Проверка Яндекса с Velt не нужна.
- Лимиты: ≤ 150 МБ на процесс, SQLite (WAL), никаких фоновых тяжёлых задач; ответы — JSON, ошибки — как в API.md.

## 2. Этапы

### Этап 1. Каркас API и HTTPS — ✅ сделано 2026-11-25 (HTTPS вживую — нет, ждём SSL хостера)
1. Роутер `/api` в `sonar/web.py` (отдельный модуль `sonar/api/`, по файлу на раздел). Общая обработка ошибок
   `{"error": {"code", "message"}}`, авторизация `Bearer <session>` (зависимость FastAPI), лимит запросов на IP
   (для `/api/auth/*` — строже, по образцу `admin/auth.py` `RateLimit`).
2. `GET /api/status` — те же поля, что бот `/status` и API.md §9 (данные уже есть в `status.py`).
3. CORS — только `https://try-sonar.ru` (сайт), клиентам не нужен.
4. Тесты на httpx `TestClient`. **Проверка вживую:** `curl https://try-sonar.ru/api/health` → 200. Если HTTPS не
   отвечает (`ERR_SSL_VERSION_OR_CIPHER_MISMATCH` — у хостера ещё нет сертификата), сказать владельцу, не чинить в коде.

### Этап 2. Аккаунт (API.md §1) — ✅ сделано 2026-11-25
1. `POST /api/auth/register`, `/login`, `/logout`; `GET/PATCH /api/me`; `PUT /api/me/password`;
   `GET /api/me/devices`, `PUT /api/me/device`, `PATCH`/`DELETE /api/me/devices/{id}` (правило 24 ч).
   Сессии — в существующей `sessions` (в базе только хэш токена), логика паролей — `accounts.py`, не дублировать.
2. Вход через Telegram и быстрая ссылка: `/api/auth/telegram/*`, `/api/auth/link*` — бот уже умеет свою половину
   (`auth_links`, BOT.md §3, §6); окно «Разрешить» (активна через 3 с) — в приложении.
3. **ПК:** экран входа / регистрации в «Аккаунте» (логин + пароль, «Войти через Telegram»), хранение сессии в
   keyring, выход, список устройств; профиль (`profile.*`) после входа берётся из `GET /me`, правки — `PATCH /me`.
   Адрес сервера по умолчанию — `https://try-sonar.ru/api` (не зашит намертво: настройка + `update.json` `api_url`).
4. **iPhone:** адрес по умолчанию в Info.plist → `https://try-sonar.ru/api`, флаг `server.enabled` → по умолчанию вкл.
   (или убрать флаг, если всё зелёное). XCTest на разбор ответов — уже есть, дополнить.
5. Строки — через `t()` на все пять языков (ПК), iPhone — свои словари.

### Этап 3. Синхронизация (API.md §6, §5) — ✅ сделано 2026-11-25 (вживую — нет)
1. `/api/sync/pull`, `/push`, `/snapshot`, `/replace` — логика как в `MemoryServer` / `store/hub.rs` (op_id не
   применяется дважды, настройки — «побеждает позднее» по `client_ts`, проигравшая — в `applied`, но победитель
   получает новый `rev`). Таблицы — по `docs/DB.md` (если чего-то нет — миграция и правка DB.md в том же коммите).
2. `POST /api/plays` (курсором, без дублей), `PUT /api/player/state`.
3. ПК: при входе `sync_target = server` (курсоры с нуля, это уже так работает), без входа — как сейчас (Wi‑Fi / офлайн).
   iPhone: `SyncTarget` — сервер, если вошёл.
4. **Проверка:** тест «два устройства через настоящий сервер» (FastAPI в памяти) — лайк на одном, есть на другом;
   вживую — лайк на ПК → на iPhone после входа в один аккаунт.

### Этап 4. Входы в сервисы на всех устройствах
`GET/PUT/DELETE /api/services/credentials` (решение владельца: вошёл на ПК — на iPhone уже подключено). Токены
шифруются Fernet-ключом сервера (`SONAR_FERNET_KEY`), отдаются только владельцу сессии, в логи не пишутся.
ПК — после входа отправить свои входы из keyring и забрать недостающие; iPhone — то же с Keychain.
Сервисы, которых на устройстве нет (Spotify без фичи и т. п.), — хранить, но не применять.

### Этап 5. Интеграции и селфбот (API.md §7)
`POST/DELETE /api/integrations/api-key`, `GET /api/me/integration`, `GET /api/oauth/now` (ключ — заголовком `Bearer`
или `?token=`, как у Dotify; задание selfbot — `docs/SELFBOT_PROMPT.md`) (формат Dotify,
из последнего `player_state`), `GET /api/oauth/profile`. **Проверка:** селфбот владельца (`selfbot`, источник
Sonar) получает «сейчас играет» с нового адреса. Ключ API в боте и в приложении — один и тот же (BOT.md §2.6а).

### Этап 6. Сайт на Velt
1. `site.yml`: собрать `site/dist` и выложить архивом `site.tar.gz` в релиз `site-latest` (не Latest, `--latest=false`).
   Деплой на GitHub Pages — убрать.
2. `sync.py`: при старте, если хэш архива сайта поменялся, — скачать `site-latest/site.tar.gz` → `site/` рядом с `app/`
   (так же атомарно, как код). Сервер раздаёт его `StaticFiles` из корня, `404.html` — для неизвестных путей
   (роутер `/@username` уже в нём). Кэш: файлы с хэшем в имени — `immutable`, HTML — `no-cache`.
3. Профиль `/@username` берёт `GET /api/public/users/{username}` (пока только шапка, API.md §1), статус — `GET /api/status`.
4. **Проверка:** `https://try-sonar.ru/` открывает главную, `https://www.try-sonar.ru/` — тоже (или редирект на без www).

### Этап 7. Сборки и обновления с сервера
1. **Админка → «Сборки»** (`ADMIN.md`): список последних сборок CI (релизы `windows-v*` и `ios-build-*` через API GitHub,
   с `GITHUB_TOKEN`, если репо приватное). Кнопка «Выпустить» → канал (релиз / бета), версия, описание (ru, en
   обязательно; остальные языки — по желанию). Сервер **сам скачивает** файлы сборки в `data/builds/<канал>/`
   (exe + `.sig`, ipa) — так не упираемся в лимит загрузки у прокси хостера. Хранить последние 3 сборки на канал,
   старые удалять. Записать в журнал админки.
2. Отдача: `GET /api/updates/windows/<канал>.json` в формате `tauri-plugin-updater` (`version`, `notes`, `pub_date`,
   `platforms.windows-x86_64.{url, signature}`), `GET /api/updates/ios/<канал>.json` в формате нынешнего
   `ios-update.json`; файлы — `/downloads/<канал>/Sonar-setup.exe`, `/downloads/<канал>/Sonar.ipa` (с `ETag`,
   `Range` для докачки; у `.ipa` — правильный `Content-Type`). `manifest.plist` для `itms-services` — тот же
   эндпоинт, что в API.md §8, под `/api`.
3. Клиенты: ПК — `endpoints` в `tauri.conf.json` → сервер, выбор канала «Релиз / Бета» в «Система → Обновления»
   (`update.channel`, sync: нет); iPhone — `UpdateChecker` на сервер, канал там же. GitHub — запасной источник
   только на переходный период, потом убрать.
4. CI: `windows.yml` перестаёт делать релиз Latest для пользователей (сборка остаётся как релиз-кандидат для админки);
   `ios-update.json` «рубильник» больше не нужен. **Переключать только когда клиенты с новым адресом уже вышли** —
   иначе старые установки останутся без обновлений. Последняя сборка, выпущенная по-старому, должна уже смотреть
   на сервер.
5. Кнопки «Скачать» на сайте и в боте (`config.py` `download_url*`) → `https://try-sonar.ru/downloads/release/…`.

## 3. Безопасность (проверить перед пушем этапов 2, 4, 7)
- Пароли — argon2 (`accounts.py`), сессии и ключи API — в базе только хэш, сравнение — `secrets.compare_digest`.
- Лимит попыток входа на IP и на логин; IP — только через `_ip` (доверенный прокси).
- Входы в сервисы: Fernet, никогда в ответах чужим сессиям, в логах, в ошибках и в бэкапе в открытом виде.
- Загрузка файлов сборок — только с `github.com` / `objects.githubusercontent.com`, имя файла — своё, не из запроса.
- Перед пушем этапов 2, 4 и 7 — навык `ponytail-review` по диффу, «Must fix» — до пуша.
