# Комнаты совместного прослушивания

Из `docs/TASTE_ROOMS_PROMPT.md` §6 (2026-11-25). Идея владельца: позвать друга и слушать **в одно и то же время**
очередь, плейлист или чьи-то Любимые — «как Rave, но для музыки».

**Рамки (не переигрывать):** сервер аудио не хранит и не отдаёт (решение 2026-11-19). Каждый играет через свой аккаунт
и со своего IP, комната синхронизирует **состояние**, а не звук. Сетевая часть — после покупки Velt и после друзей.

Демо — на моих Любимых и двух выдуманных друзьях, всё в памяти, сети нет. «Чьими глазами»: Я (хост) · Друг (диджей) ·
Второй друг (слушатель) — кнопки работают ровно по правам этой роли, через `applyOp` / `RoomCore.apply`.
«Создать комнату» и «Пригласить» неактивны. Правила менять **в обоих ядрах и тестах сразу**.

## 1. Модель

```
Room { id, host, leader, djs[], members[], queue[{ref, added_by}], pos, playing,
       anchor { server_ts_ms, position_ms }, rev, closed }
```

Роли:
- **хост** — создал комнату; единственный, кто может её закрыть; всегда может раздавать роли;
- **лидер** — чьи Play / пауза / перемотка / следующий главные (по умолчанию хост, хост или лидер передаёт);
- **диджей** — добавляет и убирает треки очереди, переставляет (хост и лидер могут это всегда);
- **слушатель** — слушает и может **предложить** трек (`suggest`, состояние не меняет — уходит лидеру и диджеям).

Правила, которые проверяет ядро и потом сервер:
- каждая принятая операция — `rev + 1`; отказ — ошибка, `rev` прежний; «ничего не поменялось» — `noop` молча;
- комната открывается **на паузе** (как у Dotify 1.3.0); зашедший получает снимок и сразу слышит текущий трек;
- ушёл лидер — пульт возвращается хосту с той же секунды; ушёл хост — комната закрывается;
- играющий трек убрать из очереди нельзя; перестановка держит `pos` на нём (`movedPos`);
- «назад» дальше 3 с — в начало трека, иначе предыдущий (как в плеере);
- участников — не больше `ROOM_MAX_MEMBERS` = 8 (потом из `GET /config`).

## 2. Синхронизация

- Якорь: `(server_ts_ms, position_ms)` в момент Play / паузы / перемотки / смены лидера. Позиция сейчас =
  `position + (server_now − server_ts)`, пока `playing`.
- Новый трек (`next` / `prev` / `jump`) — якорь **в будущем**: `server_now + 1500 мс`, позиция 0. Клиент заранее
  прогревает поток, ждёт (`wait`) и стартует вовремя.
- Часы: 5 пингов, берётся пинг с минимальным RTT, сервер считается ответившим посередине пути (`clockOffset`).
  Ошибка — не больше половины RTT.
- Подстройка слушателя (`syncAction`): расхождение < 250 мс — ничего; 250 мс … 2 с — скорость 1 ± 3 %; больше 2 с или на
  паузе — `seek`. Секунду при 3 % догоняем примерно за 33 с — поэтому выше 2 с сразу перематываем.
- Недоступный у слушателя трек — резерв (`services/fallback.rs`, `Fallback.swift`); нет и резерва — у слушателя пропуск,
  в комнате видно «нет трека у тебя».
- Звук (эквалайзер, пространство, реверб, «Для этого трека») — **у каждого свой**, скорость в комнате всегда 1×
  (рекомендация; вопрос (а) ниже). Сведение (`player/blend/`) в комнате выключено: DJ-переход сдвигает время.

## 3. Протокол (черновик — дополнит `docs/API.md` «Комнаты»)

WebSocket `/rooms/{id}`. Клиент → сервер: `join`, `leave`, `op { type, …, client_rev }`, `suggest { ref }`, `ping { t0 }`.
Сервер → клиент: `state` (полный снимок с `rev`), `error { code }`, `suggested { by, ref }`, `pong { t0, server_ts }`.
Имена операций и ошибок — как в ядре (`RoomOp`, `RoomError`). Сервер — источник истины: клиент шлёт намерение,
показывает его только после `state` с бо́льшим `rev` (`acceptSnapshot`). После обрыва — `join` и новый `state`.

Нагрузка на Velt (512 МБ / 25 % vCPU): комнат единицы, сообщения — десятки байт; один процесс бота с `websockets` держит.

## 5. Критика (честно)

- Самая рискованная часть списка. «В одно и то же время» реально с допуском в сотни миллисекунд, не точнее: HLS
  SoundCloud стартует с сегмента, `<audio>` / AVPlayer сообщают позицию с запаздыванием, один трек в Яндексе и SoundCloud
  может отличаться вступлением на секунды. Пока точность не измерена на живых потоках (шаг 1), обещать нечего.
- Демо-экран до сервера — предпросмотр, а не проверка идеи: он показывает роли и права, но ничего не говорит про
  синхронизацию. Ценное в этой части — ядро с тестами, его возьмёт сервер.
- Без друзей комната бессмысленна. Порядок: сервер → друзья и ЛС → комнаты, не наоборот.
- «Любимые друга» как источник требуют, чтобы они были открыты (`privacy.likes`) и играли у слушателя (резерв).

## 6. Вопросы владельцу

(а) **Звук комнаты** — у каждого свой (рекомендую, сейчас так в демо) или как у Dotify — из настроек хоста?
(б) **«Любимые друга»** — брать только открытые (`privacy.likes` = все / друзья) или каждый раз спрашивать друга?
(в) **Лимит участников** — 8 (как «Вечеринка» у Dotify) или другой; и платно ли (Sonar Deep) больше 8?
