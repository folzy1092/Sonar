# Сведение — спека (Windows-клиент, локально)

> Решение владельца **2026-11-23**. Сначала только ПК, iPhone — потом (§13). Сервер не нужен.
> Название функции в интерфейсе — **«Сведение»** (en *Blend*, uk «Зведення», es «Mezcla», de «Übergang»,
> pl «Miks»). Не «микс» — это Sonar Mix, не «кроссфейд» — кроссфейд остаётся отдельно и бесплатно.
> **Всё сведение — за подписку Sonar Deep** (§11). Эта спека — что строим, как работает, в каком порядке
> делать и как проверять.

## 0. Что строим

Режим перехода между треками «как у диджея»: Sonar заранее анализирует текущий и следующий трек
(темп, сетка долей, такты, фразы, тональность, энергия), выбирает момент выхода из одного и момент входа в
другой и сводит их за ~6–16 секунд: бит в бит, с плавной подгонкой темпа, сдвигом тона на время перехода и
эквалайзером по полосам (низ / середина / верх). Сценарий владельца — включил плейлист на тусе, и всё
сочно, без дыр и каши, перетекает одно в другое.

Пять видов перехода + Авто, пользователь выбирает сам:

| Ключ | Название | Суть | Темп свести обязательно |
|---|---|---|---|
| `auto` | Авто | движок выбирает вид и момент под каждую пару треков | — |
| `bass` | Бас-свап | оба трека играют вместе, у входящего срезан бас; на сильную долю бас меняется местами | да |
| `filter` | Фильтр | на уходящем закрывается фильтр низов (HPF), на входящем открывается фильтр верхов (LPF) | да |
| `echo` | Эхо | уходящий тонет в эхе к концу фразы (сухой гаснет за полтакта), входящий выходит за такт | нет |
| `smooth` | Плавный | длинное смешивание громкостью и эквалайзером, без резких мест | желательно |
| `drop` | На дроп | подъём фильтром на уходящем, его хвост эха и резкий вход входящего сразу на его дроп | желательно |

Чего **нет и не будет** в этой версии: разделения на дорожки (вокал / бит / бас отдельно, как Serato
Stems) — только эквалайзер и фильтры; «Сравнить звучание» из чужой панели; сведения при ручном
переключении (§6.1); iPhone.

### Решения владельца (2026-11-23), откуда что взялось

1. Название — «Сведение».
2. Кнопка в плеере — **слева от кнопки «Скорость и тональность»** (`SpeedButton`), всплывашка с выбором.
3. В настройках «Аудио» — рядом с кроссфейдом, выбор «Переход между треками»; кроссфейд и сведение
   одновременно не работают.
4. **Сведение — только когда трек доигрывает сам.** «Следующий», клик по треку, выбор из очереди —
   обычное переключение без сведения (и без быстрого варианта).
5. Анализа нет (трек не скачан или не посчитан) — откат на кроссфейд, без ошибок и пауз.
6. Сколько можно срезать с конца и начала трека — **регулирует пользователь**, рекомендуемое значение
   выставлено по умолчанию (§7.3).
7. Своя скорость трека («Для этого трека», Slowed / Sped up) — переход начинается на скорости текущего,
   заканчивается на собственной скорости следующего.
8. Тон — на время перехода максимум ±2 полутона, потом плавно назад; сильнее не сочетается — Авто берёт «Эхо».
9. Громкость двух треков выравнивается на время перехода.
10. **Пока уходящий трек не доиграл, везде показывается он** (название, обложка, полоса, мини-окно,
    Discord, SMTC, «сейчас играет»). Доиграл — показывается следующий.
11. Пауза, перемотка, повтор одного, последний трек, перемешивание, Sonar Mix — §6.
12. **ПКМ по плейлисту → «Свести для вечеринки»** — переставить треки под гладкие переходы и играть
    сведением (§9). Платно.
13. Оценка прошлого перехода 👍 / 👎 — в первой версии (§8.4).
14. Отладочная панель как на скринах владельца — только подписке Dev (`@folzy`) или по скрытой галочке (§10).
15. Платно — всё сведение (Sonar Deep).
16. Без разделения на дорожки.

## 3. Звуковой тракт: своя цепочка у каждого дека

Сейчас: `деки → свои Gain → mix → эквалайзер → выравниватель → тон+реверб → анализатор → выход`.

Станет:

```
дек A → DeckChain A ┐
                    ├→ mix → эквалайзер пользователя → выравниватель → реверб → анализатор → выход
дек B → DeckChain B ┘

DeckChain = gain (громкость перехода и выравнивание громкости)
          → low  (lowshelf 180 Гц)     ┐ «изолятор» на три полосы, каждая −40…+6 дБ
          → mid  (peaking 1 кГц, Q 0.7) ├ (−40 дБ = полоса выключена)
          → high (highshelf 3.2 кГц)   ┘
          → hp → lp (два BiquadFilter, частота и Q автоматизируются; в покое hp на 10 Гц, lp на Найквисте —
                     прозрачны; два узла вместо одного со сменой типа — смена типа на ходу щёлкает)
          → echo send (DelayNode + обратная связь через HPF 300 Гц; в покое — send = 0)
          → pitch (тот же worklet sonar-pitch: тон пользователя для ЭТОГО трека + сдвиг перехода)
```

- Тон пользователя переезжает из общего `Effects` в цепочку дека: иначе во время перехода тон трека A
  применяется и к B. Реверб остаётся общим.
- Обход: узел с нейтральными значениями стоит в цепочке всегда (переподключение на ходу щёлкает).
  Исключение — pitch: при тоне 0 и без перехода worklet отключается, как сейчас (экономия CPU), включение —
  с перекрытием громкости 30 мс.
- Все изменения параметров — только через `setTargetAtTime` / `linearRampToValueAtTime`, минимум 5 мс
  (иначе щелчки). Резкие места перехода («свап», «срез») — 5–12 мс.
- Выравниватель на время перехода **замораживается** (держит текущее усиление), громкости выравнивает сам
  переход по замеру из анализа (§4.6); после перехода выравниватель отпускается плавно (0.4 с).
- Шаг 1 работы (§12) — переделать тракт **без изменения поведения**: кроссфейд, эквалайзер, тон, реверб,
  выравниватель звучат как раньше.

## 4. Анализ трека

### 4.1. Откуда файл

Анализу нужен трек **целиком**. Команда Rust `blend_source(ref) -> { url, temp }` (трек ей не нужен —
качает тот же `stream::fetch_into`, что кэш, по одному `ref`):

1. Трек в `track_cache` — URL локального аудио-сервера на него.
2. Нет — скачать целиком тем же кодом, что качает кэш (для HLS SoundCloud — склейка кусков), в
   `<кэш>/blend-tmp/`. Если кэш включён — после скачивания файл ложится в кэш как обычно; если выключен —
   удаляется после анализа (`blend_release(ref)`) и при запуске (как `.part`).
3. Локальные файлы (`local/`) и «Скачанное» — читаются как есть.
4. Предел — 60 МБ и 30 с на скачивание; не уложились — анализа нет, будет кроссфейд (решение 5).

Не больше **2** скачиваний+анализов одновременно (`analyze-queue.ts`); приоритет: играющий и следующий >
пул вечеринки. Сам расчёт — в одном воркере, по очереди; параллельно идут скачивание и декод.
Готовый анализ той же версии сначала ищется в базе. Не вышло (офлайн, не скачался) — трек помечается и
не пробуется на каждом переключении; пометки сбрасываются, когда выключили офлайн-режим.
Файл берётся с локального аудио-сервера, поэтому `analyze.svelte.ts` — в списке исключений сторожа
`lib/offline-net.test.ts`. В офлайне трек с диска анализируется, качать — нет (`offline::guard`).

### 4.2. Декодирование

В WebView: `fetch(url) → ArrayBuffer → new OfflineAudioContext(1, 1, 11025).decodeAudioData(buf)` (число
каналов контекста на декод не влияет — `AudioBuffer` приходит со всеми каналами файла).
`decodeAudioData` декодирует всё, что играет `<audio>` (mp3, AAC/fMP4, FLAC, Opus/WebM YouTube, Vorbis
Spotify), и сразу пересэмплирует в 11 025 Гц. Каналы сводятся в моно уже в воркере. Память: 5 минут стерео
на 11 025 Гц — ~26 МБ, держим не больше двух буферов. PCM уходит в воркер через transfer (без копии).

### 4.3. Что считает анализатор (`analysis.ts`, в воркере)

Все функции чистые, на вход `Float32Array` моно 11 025 Гц. Кадр STFT 1024 отсчёта, шаг 256 (~23 мс), окно Ханна.

1. **Тишина по краям** — первый и последний кадр с RMS выше −50 дБ от пика: `startMs`, `endMs`.
2. **Огибающая атак** — спектральный поток (положительная разность модулей) по полосам: низ (< 200 Гц,
   «бочка»), середина, верх; общая огибающая — взвешенная сумма, сглаживание и вычитание скользящего среднего.
3. **Темп** — автокорреляция общей огибающей в диапазоне 60–200 BPM, сглаженная гауссом вокруг 120 BPM
   (против ошибки «вдвое»); затем уточнение параболой по пику. Темп приводится в 70–180. `bpmConf` 0…1 —
   высота пика над фоном. Уточнение — не парабола, а перебор темпа (±3 % шагом 0.1, затем ±0.15 шагом 0.01)
   и фазы по самой огибающей: лаг автокорреляции шагает кадрами по ~23 мс, этого мало. Против «вдвое
   медленнее»: если между долями атак не меньше 0.8 от атак на долях — темп удваивается.
   Огибающая сдвинута на 13 мс позже середины кадра: поток атак «видит» удар раньше (подобрано по щелчкам).
4. **Сетка долей** — фаза: перебор сдвигов с шагом 5 мс, максимум суммы огибающей в точках сетки. Темп
   считается постоянным (электроника, поп, рэп). Проверка дрейфа: у каждой трети трека свой темп и фаза,
   соседние сетки сравниваются на стыке третей (тихие трети — пауза — не участвуют); расходятся больше чем
   на 40 мс — `gridStable = false` (живой барабанщик, смена темпа) — с таким треком бит-синк не делаем
   (§7.2). `firstBeatMs` может быть раньше `startMs` (сетка продолжена назад в тишину).
5. **Такты** — 4 доли. Какая доля «раз»: фаза 0…3 с максимумом атак в низкой полосе и сменой гармонии
   (хромы) на ней.
6. **Энергия по тактам** — RMS всего и низа, плотность атак, «середина» (300 Гц–3 кГц, грубый признак
   вокала) — массивы по тактам.
7. **Фразы** — границы по 8 тактов, уточнённые «новизной»: матрица сходства тактов по хроме + энергии,
   ядро Фута; граница фразы — пик новизны на кратном 4 такте. Метки считаются от медианы энергии **без
   крайних фраз** (иначе тихие интро и аутро тянут её вниз и дроп не отличить от тела): `intro` (энергия
   ниже 60 % от медианы в начале), `outro` (то же в конце), `build` (энергия растёт 4+ такта подряд), `drop` (скачок энергии
   и низа ≥ 1.6× после `build` или тихой фразы), `body`.
8. **Тональность** — хрома: бины спектра с 55 Гц до 2 кГц сворачиваются в 12 классов, усреднение по треку
   с весом энергии; корреляция с профилями Темперли (мажор и минор, 24 тональности). `key` 0…23,
   `keyConf` 0…1 — разница лучшей и второй, умноженная на чёткость хромы (у шума все классы почти равны,
   и корреляция там случайна). `keyConf < 0.15` — тональность «не знаем».
9. **Громкость** — интегральная, грубый LUFS: K-фильтр (shelf + HPF) и средняя мощность по блокам 400 мс
   с отсечкой тихих (−70 и −10 от среднего), как в BS.1770, без претензий на точность ±1 LU.

Версия анализатора — константа `ANALYSIS_VERSION`; поменяли алгоритм — старые результаты пересчитываются
при следующем проигрывании.

Цель по скорости: трек 4 минуты — анализ ≤ 1.5 с в воркере на ПК владельца (без скачивания и декода).

### 4.4. Результат

```ts
export interface BlendAnalysis {
  version: number
  ref: string
  durationMs: number
  startMs: number; endMs: number          // без тишины по краям
  bpm: number; bpmConf: number
  beatMs: number                          // длина доли, 60000 / bpm
  firstBeatMs: number                     // первая доля сетки
  downbeat: 0 | 1 | 2 | 3                 // какая доля сетки — «раз»
  gridStable: boolean
  key: number | null; keyConf: number     // 0…11 мажор, 12…23 минор
  loudness: number                        // ~LUFS
  bars: { energy: number[]; low: number[]; mid: number[]; onsets: number[] }  // по тактам, 0…1
  phrases: { bar: number; kind: 'intro' | 'body' | 'build' | 'drop' | 'outro' }[]
}
```

### 4.5. Когда анализируем

- Трек начал играть → в очередь анализа **он сам** (если нет) и **следующий** по очереди.
- Следующий поменялся (вставили «играть следующим», перемешали, волна подложила) — анализ нового;
  план перехода пересчитывается, пока переход не начался.
- Только если сведение включено и подписка позволяет (§11).

### 4.6. Громкость перехода

Входящий трек получает множитель `10^((LA − LB)/20)`, ограниченный ±9 дБ, где LA, LB — `loudness`.
После перехода множитель за 2 с уходит к 1, а выравнивание дальше делает обычный выравниватель (если включён).

## 5. Хранение — миграция № 17

```sql
CREATE TABLE blend_analysis (
  ref TEXT PRIMARY KEY, version INTEGER NOT NULL, data_json TEXT NOT NULL, analyzed_at INTEGER NOT NULL
);
CREATE TABLE blend_ratings (
  id INTEGER PRIMARY KEY, from_ref TEXT NOT NULL, to_ref TEXT NOT NULL, kind TEXT NOT NULL,
  score INTEGER NOT NULL, at INTEGER NOT NULL
);
CREATE INDEX blend_ratings_kind ON blend_ratings(kind, at);
```

- Только локально, не синхронизируется (анализ одинаков на любом ПК, оценки — личный вкус к переходам;
  синк оценок — когда будет сервер, отдельным решением).
- Команды: `blend_get(refs) -> map<ref, { version, data }>`, `blend_put(ref, version, json)`,
  `blend_rate(from, to, kind, score)`; `kind` — `bass | filter | echo | smooth | drop`.
- Хранилище («Система → Хранилище», группа «Данные») — строка «Анализ для сведения: N треков, размер» и
  «Очистить» (`clear_storage('blend')`). Очистка кэша треков и прочего анализ **не** трогает: это минуты
  расчёта, а не место на диске; оценки переходов не стираются вовсе.
- `docs/DB.md` — дописать обе таблицы в том же коммите.

## 6. Как идёт переход (контроллер)

### 6.1. Когда срабатывает

Только при естественном окончании трека: `maybeCrossfade` проверяет `audio.blend` раньше кроссфейда.
Сведение **не** запускается: при «Следующий», клике по треку, выборе из очереди, перемотке за точку выхода
вручную (тогда — обычный конец трека с кроссфейдом-подстраховкой), при `repeat === 'one'`, на последнем
треке очереди без повтора, если трек короче 60 с, если анализа A или B нет.

### 6.2. Состояния

```
idle → planned (план есть, ждём момента) → prerolling (B загружен и стоит на паузе в точке входа)
     → running (оба играют, автоматизация идёт) → promoting (A затих: B становится текущим) → idle
     ↘ fallback (анализа нет / B не успел загрузиться) — обычный кроссфейд
     ↘ cancelled (пауза-перемотка-переключение, §6.4)
```

- `prerolling` — за 8 с до точки старта: B грузится во второй дек (`api.streamUrl`, как прогрев), ставится
  `currentTime = точка_входа − упреждение`, громкость дека 0, цепочка в стартовом положении перехода.
  Не загрузился к моменту старта — fallback.
- Старт B — в момент, когда до доли «раз» A в точке старта осталось столько, сколько B играет до своей доли
  «раз» в точке входа; `play()` вызывается на 150 мс раньше, а точная фаза добивается подстройкой (§6.3).

### 6.3. Темп и бит-синк

Обозначения: `BA`, `BB` — темп из анализа; `rA` — текущая скорость A (с учётом «Для этого трека» и Slowed);
`rB` — собственная скорость B (сохранённая для трека или 1). Эффективный темп `TA = BA·rA`, `TB = BB·rB`.
Учитываем «вдвое» / «вполовину»: если `TB/TA` ближе к 2 или 0.5, чем к 1, B считается в удвоенной / половинной сетке.

- Общий темп переходит из `TA` в `TB` по smoothstep за всю длину перехода: `T(t) = TA + (TB − TA)·s(t)`.
  Скорости дек: `rateA(t) = T(t)/BA`, `rateB(t) = T(t)/BB`. Обновление `playbackRate` — каждые 50 мс
  (тайм-аут, не кадры: окно может быть в трее).
- Если `|TB/TA − 1|` больше допуска `audio.blend_tempo` (§7.3) — бит-синк невозможен: каждый дек на своей
  скорости, в карточке — «без бита». **Ручной вид остаётся собой** (решение после проверки владельца 2026-11-24:
  раньше бас-свап, фильтр и дроп молча подменялись «Эхом», и любой выбор звучал одинаково — обрывом). Авто без
  синка выбирает из фильтра, эха и плавного (бас-свап и дроп на двух разных сетках — каша).
- `preservesPitch` у каждого дека как у его трека (связанная скорость — тон едет вместе со скоростью; так и
  задумано пользователем для этого трека).
- **Фаза**: каждые 50 мс считаем ошибку — где сейчас доля B относительно доли A по `currentTime` обеих дек
  и их сеткам. Ошибка > 8 мс — поправка скорости B на ±0.5…2 % пропорционально ошибке, на 200–400 мс;
  ошибка > 120 мс (рывок, подгрузка) — B перематывается к нужной фазе за 10 мс тишины в полосах (только
  до момента свапа; после свапа — терпим, переход уже почти закончен).
- Цель: расхождение долей **≤ 20 мс** на всём протяжении синхронного перехода (видно в отладке).

### 6.4. События во время перехода

| Событие | Что делаем |
|---|---|
| Пауза | обе деки на паузу, автоматизация и часы перехода стоят; продолжить — обе играют, фаза добивается §6.3 |
| Перемотка (полоса — это трек A, решение 10) | переход отменяется: B затухает за 300 мс и останавливается, цепочка A возвращается в нейтраль за 300 мс, A играет с новой позиции; план перехода пересчитывается |
| «Следующий» | переход завершается сразу: A гаснет за 300 мс, B (уже играющий) становится текущим со своей позиции |
| «Предыдущий» / клик по треку / новая очередь | переход отменяется, B останавливается, дальше как обычно |
| B упал с ошибкой | A доигрывает как без перехода, следующий трек — обычным путём |
| Выключили сведение в кнопке | идущий переход доигрывается, следующие — нет |
| Сменили вид перехода в кнопке | действует на следующий план; если переход ещё не начался — план пересчитывается сразу |

### 6.5. Что видно, пока идёт переход (решение 10)

- `player.current`, `pos`, полоса прогресса, время, тексты песен, SMTC, Discord RPC, мини-окно, оверлей,
  `player_state` — **трек A до конца его затухания**. Во время перехода полоса A не обрывается: конец полосы —
  точка, где A замолкает (не `duration`).
- В момент `promoting` — смена на B **без перезагрузки**: B уже играет во втором деке, `load()` не зовётся,
  а есть отдельный путь «принять играющий дек» (обновить `pos`, `audio`, `hls`, часы, `tempo.trackChanged`,
  медиа-сессию). Анимация смены трека (обложка, фон) — как при обычной смене.
- Мелкий значок на кнопке сведения и строка «Сводим → <B>» в мини-плеере под названием, пока идёт переход.
- Прослушивания: A — `listenedMs` до конца (обрезка концовки не считается пропуском, `skipped = false`);
  B — начинает копить `listenedMs` с момента своего старта в переходе.

### 6.6. Как сделано (Э4, сверено с кодом 2026-11-23)

Контроллер — `blend/controller.svelte.ts` (чистый, тесты на поддельных деках), хост для настоящего плеера —
`blend/player-host.ts`, плеер принимает B через `adoptDeck`. Отличия от текста выше:

- `rateB` включает поправку «вдвое / вполовину» (`beatRatio` плана), а не только `T(t)/BB`.
- B стартует беззвучно **за 2 такта** до своего входа (громкость 0 по кривой): за это время фаза успевает
  сойтись. `play()` — до 150 мс раньше, с позиции, рассчитанной на текущий такт; если она раньше начала файла —
  ждём один тик.
- `promoting` наступает в точке, где A замолкает (`endAMs`), а не по окончании файла. В «Эхо» хвост эха
  дозвучивает уже после смены текущего трека: цепочку A не рвём, дек A останавливаем, send эха открыт до конца хвоста.
- «Следующий» после смены на B — уже про трек после B: `finishNow()` → `false`, `load()` зовёт `abort()`.
- Отложенные освобождения дек выполняются сразу при новом преролле (старый таймер не убьёт свежий B).
- B не готов за 10 с (`LOAD_TIMEOUT_MS`) или к такту старта — fallback; кроссфейд-подстраховка при включённом
  сведении и `audio.crossfade = 0` — 6 с (`BLEND_FALLBACK_MS`).
- Пока идёт переход, выравниватель громкости стоит (`leveler.hold`), а меню скорости не трогает `playbackRate`
  дек — им управляет контроллер; после перехода звук B возвращается к его своему (`applySpeed`).

## 7. Планировщик (`planner.ts`)

### 7.1. Кандидаты

Перебор идёт по тактам, фразы не фильтр, а оценка (слагаемое «фразы» в §7.2) — так план есть и у трека без
выраженных фраз. Такт `k` трека начинается в `firstBeatMs + (downbeat + 4k)·beatMs`.

- **Якорь A** — такт, на котором A замолкает: от `endA − cut` (`cut` — `audio.blend_cut`) до такта за `endA`,
  но **не за концом файла**: A должен доиграть свою часть перехода (у «Эха» — ещё полтакта затухания) с запасом
  300 мс, иначе конец файла оборвёт переход. Начало перехода — якорь минус «разгон» вида (ниже), раньше
  `startA` — нельзя. Конец A в плане — `endAMs`. Якорь прямо перед фразой `outro` A оценивается как конец музыки:
  широкий «Можно срезать» даёт уйти до аутро, узкий — нет; без причины (фраз, энергии) план всё равно у конца.
- **Вход в B** — такты B с позицией `[startB, startB + cut]`; начало фразы B, `intro` и такт 0 оцениваются
  выше, для «На дроп» — начало фразы `drop` (иначе вход с меньшей оценкой, вид получает штраф «вида»).
- Длина перехода: `audio.blend_length` (Коротко ~6 с · Норм ~10 с · Длинно ~16 с) переводится в такты при темпе A
  и округляется **до целого такта, от 4 тактов — до чётного** (2…32; чётные ровнее ложатся на фразы, а три длины
  всё равно различаются при любом темпе от 60 до 174). Раньше — до ближайшего из 4 / 8 / 16, и при 145 уд/мин «Норм» и
  «Длинно» давали одни и те же 8 тактов, при 93 — «Коротко» и «Норм» одни и те же 4. По видам (все растут с длиной):

| Вид | Тактов | B стартует (`inAtBar`) | A замолкает |
|---|---|---|---|
| Бас-свап, Фильтр | длина | сразу | в конце |
| Плавный | 2 × длина, не больше 32 | сразу | в конце |
| Эхо | разгон + хвост: разгон 2 при длине ≥ 6, иначе 1; хвост — половина длины, не меньше 2 | после разгона | полтакта после «раз», дальше только хвост эха |
| На дроп | половина длины вверх, не меньше 2 | в конце разгона, на дроп | там же |

Срезано с конца A — `max(0, endA − endAMs)`, с начала B — `max(0, inMs − startB)`; оба не больше `cut`.

### 7.2. Оценка пары «выход — вход — вид»

Сумма весов, всё 0…1, больше — лучше:

| Слагаемое | Вес | Смысл |
|---|---|---|
| темп | 3 | `1 − |TB/TA − 1| / допуск`; вне допуска — 0 и вид без синка |
| тональность | 2 | совместимость по Camelot после разрешённого сдвига (§7.4); «не знаем» — 0.5 |
| энергия | 2 | энергия A в последних тактах выхода близка к энергии B в первых тактах входа |
| фразы | 1.5 | выход на конце фразы A, вход на начале фразы B; `outro` A и `intro` B — максимум |
| обрезка | 1 | меньше срезано — лучше |
| вокал | 1 | штраф, если «середина» высока у обоих в зоне наложения (две песни поверх друг друга) |
| вид | 1 | подходит ли вид этой паре (§7.5) |
| оценки | 0.5 | 👍 / 👎 к этому виду за последние 60 дней (§8.4) |

Итог — взвешенная сумма, делённая на сумму весов (12), то есть 0…1. Уточнения по коду:

- темп: B сравнивается и в удвоенной / половинной сетке (`beatRatio` 2 или 0.5), допуск 0 — только точное совпадение;
- тональность у «Эха» и «На дроп» (наложения почти нет): `max(0.5, совместимость без сдвига)`, тон B не сдвигаем;
  у долгих видов — после разрешённого сдвига при скорости B, с которой он сядет в сетку A (§7.4);
- энергия — среднее двух тактов A перед якорем против двух первых тактов B; вокал — средняя «середина» в зоне
  наложения, штраф с 0.5, только у видов с наложением;
- оценки: 👎 снижают до 0, 👍 не поднимают выше 1 — лайк не должен перебивать музыку;
- громкость B под A: `LA − LB`, не больше ±9 дБ; тишина (≤ −70 LUFS) у любого — 0.
  Поправка только **убавляет** (громкий B входит приглушённым, громкий A притихает к уровню B) и к концу перехода
  (`endBar`) плавно в дБ уходит в 1 — `trimAt` / `BlendTimeline.trim` (2026-11-25: раньше тихий B весь переход
  звучал на +N дБ и после перехода за 2 с «проседал»).

`gridStable = false` у любого — без синка: Авто выбирает из фильтра, эха и плавного, ручной вид идёт как есть
на своих скоростях.

Результат — **топ-8** вариантов (`момент 1 из 8`), кнопка «Другой момент» берёт следующий.
Планировщик — чистая функция `plan(a, b, opts) → TransitionPlan[]`, детерминированная (тесты).

### 7.3. Настройки, на которые он смотрит

| Ключ | Значения | По умолчанию | Где |
|---|---|---|---|
| `audio.blend` | вкл / выкл | выкл | кнопка, Аудио |
| `audio.blend_type` | `auto` `bass` `filter` `echo` `smooth` `drop` | `auto` | кнопка, Аудио |
| `audio.blend_length` | 6 · 10 · 16 (с) | 10 | кнопка, Аудио |
| `audio.blend_cut` | 0…45 с, шаг 1 | **16** (на ползунке — отметка «рекомендуется») | кнопка, Аудио |
| `audio.blend_tempo` | допуск темпа 0…12 %, шаг 1 | 8 | Аудио |
| `audio.blend_key` | подгонять тональность | вкл | кнопка, Аудио |
| `audio.blend_debug` | отладочная панель | выкл, видна только Dev | Аудио (скрыто) |

`audio.crossfade` при включённом сведении не обнуляется: его длина — длина кроссфейда-подстраховки
(0 — подстраховка 6 с). Ключи — в `lib/settings.svelte.ts`, поиск по настройкам — `lib/settings-catalog.ts`,
каталог — `docs/SETTINGS.md`.

### 7.4. Тональность и Camelot (`camelot.ts`)

- Совместимы: та же клетка, ±1 по кругу, мажор ↔ параллельный минор (тот же номер). Энергичный буст +2
  (`+2` по кругу) — совместим с весом 0.6.
- Если `audio.blend_key` включён и тональности несовместимы: ищем сдвиг B на `s ∈ [−2, +2]` полутона, при
  котором станут совместимы (с учётом того, что связанная скорость сама сдвигает тон на `12·log2(rate)`).
- Сдвиг применяется к B с начала перехода и уходит в 0 за 8 тактов после конца перехода (плавно, тон
  «доезжает» — так и задумано). Нужен больше ±2 — сдвига нет, а у видов с долгим наложением (бас-свап,
  плавный, фильтр) штраф; Авто уходит в «Эхо» или «На дроп».

### 7.5. Авто: какой вид

| Условие пары | Вид |
|---|---|
| тон не совместить | Эхо |
| темп вне допуска или сетка нестабильна (без синка) | Фильтр (мягче всего), реже Эхо или Плавный |
| оба спокойные (энергия < 0.4, мало атак) | Плавный |
| у A есть `outro`, у B — `intro` с бочкой, темп близок | Бас-свап |
| у B вход на фразе `drop` (лучше всего — A перед ним громкий, энергия > 0.6) | На дроп |
| спектры сильно разные (у одного много низа, у другого — верха) | Фильтр |

Это не жёсткие правила, а бонус слагаемого «вид» в §7.2; побеждает лучшая сумма.

## 8. Пять видов перехода по тактам (`curves.ts`)

`curves.ts` — чистая функция `curvesFor(plan, nyquist)`: кривые обеих цепочек ключевыми точками по тактам
(громкость, low / mid / high, фильтр, эхо); значение на такте — `valueAt` (частоты — по экспоненте, громкость —
равной мощностью), темп — `tempoAt`. Контроллер только применяет их рампами (`automation.ts`: ключевые такты —
точно, между ними — выборки каждые 100 мс). Отличия от таблиц ниже (сверено с кодом в Э4): в «Плавном» басы
встречаются на −3 дБ каждый; в «Фильтре» бас B возвращается, когда HPF у A проходит 150 Гц. Ниже `N` — длина в тактах, такты считаются от начала перехода. «−∞» = −40 дБ.

### 8.1. Бас-свап (N тактов, свап на N/2)

Форма — по разбору автодиджея Vande Veire & De Bie (2018, их «rolling» / «double drop»; только идея и уровни,
код AGPL не брали): B входит одной серединой и тише, басы меняются на фразе, A после свапа держится и гаснет
второй половиной остатка. `d` — один такт (на переходе короче 8 тактов — `N/8`).

| Такты | A | B |
|---|---|---|
| 0 | всё 0 дБ | громкость 0, low −∞, high −∞ |
| 0 → d | — | громкость → 0.2 |
| d → N/4 | — | громкость → 0.8 (равная мощность), дальше держится |
| N/4 → N/2 | — | high −∞ → −20 дБ |
| **N/2, на «раз»** | **low → −∞ за 8 мс** | **low → 0 за 8 мс** — свап |
| N/2 → N/2 + d | громкость → 0.8, high → −20 | громкость → 1, high → 0 |
| до ¾ N | high → −∞ | — |
| ¾ N → N | громкость → 0 (равная мощность) | — |

Раньше B сразу шёл с верхом и за четверть перехода выходил на полную, а A гас за последний такт — две пары
тарелок звенели вместе, и конец звучал как обрыв. Свап — на начале фразы B: планировщик ценит вход, при котором
свап падает на фразу B (лучше всего на `drop`), не меньше входа на интро (§7.2); для этого нужен «Можно срезать»
больше длины интро B.

### 8.2. Фильтр (N = 8)

- A: highpass от 20 Гц до 1.2 кГц по экспоненте за N тактов, Q 0.7 → 3 к последним двум тактам (лёгкая
  «вой» резонанса), громкость → 0 на последнем такте.
- B: lowpass от 300 Гц до 20 кГц по экспоненте, Q 0.7; громкость 0 → 1 за первые 2 такта.
- Низы: пока HPF у A ниже 150 Гц, у B low −12 дБ (два баса не дерутся), на середине — B low → 0 за такт.

### 8.3. Эхо (разгон 1–2 такта, хвост 2+ такта)

- Эхо набирается весь разгон: send 0 → 1 от начала перехода до последней доли перед «раз», обратная связь
  0 → 0.55, задержка = ¾ доли A, HPF в петле 300 Гц.
- На «раз» сухой A гаснет за полтакта (равная мощность), а не за 12 мс — прежний обрыв владелец слышал как
  «трек просто обрывается» (2026-11-24). A отпускают (промоут), только когда он замолк.
- B входит на этот «раз»: громкость 0 → 1 за такт, low −∞ → 0 за 2 такта — не стеной.
- Хвост эха затухает сам (обратная связь 0.55 → 0.3 к концу перехода), потом send 0 и A останавливается.
- Темп не сводится: B сразу на своём. Тон не сдвигается.

### 8.4. Плавный (N = 2 × длина, до 32)

- Громкость — равная мощность (sin/cos) на всю длину.
- low: у A → −∞ с середины до ¾; у B −∞ → 0 с ¼ до середины (басы встречаются на середине при уровнях
  ≤ −6 дБ каждый).
- mid и high — линейно навстречу.
- Темп — если в допуске, сводится; если нет — без синка, B на своём темпе (каша не страшна: громкости малы).

### 8.5. На дроп (N = половина длины, от 2)

- A, весь разгон перед концом своей фразы: highpass 20 Гц → 800 Гц, громкость −3 дБ, на
  последнем такте — mid +3 дБ (подъём «напряжения»).
- Последний такт разгона A набирает эхо (send 0 → 1 к последней доле, обратная связь 0.45).
- На «раз»: A → 0 за 5 мс, B стартует со своего `drop` на полной громкости за 5 мс; хвост эха A звенит поверх
  дропа ещё 2 такта и глохнет.
- Темп: последние 4 такта A догоняет темп B (в пределах допуска); B сразу на своём.

### 8.6. Оценка прошлого перехода

После каждого перехода в кнопке и отладке — «Как переход? 👍 / 👎» (значки MingCute, не эмодзи) на 60 с;
ответ → `blend_rate(from, to, kind, ±1)`. В Авто: вид с перевесом дизлайков за 60 дней теряет до 0.5 в оценке.

Как сделано (Э7): вопрос ведёт `player/blend/ratings.svelte.ts` — открывается по `done` контроллера (ставится только при
доводке, отменённый переход не спрашивает), строка 👍/👎 — общий `player/BlendRate.svelte` в всплывашке кнопки и в
отладке; пока вопрос висит, на кнопке точка (всплывашка сама не открывается — только кликом). Ответ один на переход;
не записалось — можно ответить ещё раз. Перевес — `blend_balance(since)` (Rust, среднее `score` по виду), уходит в
планировщик через `BlendSettings.ratings` (`currentBlendSettings`): балл `rating` = 1 + перевес, если перевес меньше нуля (вес 0.5 — отсюда «до 0.5»).

## 9. «Свести для вечеринки» (ПКМ по плейлисту)

- Пункт в `PlaylistMenu` у своих плейлистов, «Любимых» и плейлистов сервисов: **«Свести для вечеринки»**,
  значок — свой (два диска).
- Что делает: включает сведение **на эту очередь** (настройку `audio.blend` не трогает: заменил очередь —
  вечеринка кончилась), вид — из `audio.blend_type`, и сам выбирает порядок треков.
- Порядок — по ходу, а не заранее (анализ 200 треков заранее — это минуты и гигабайты):
  1. Старт — сразу: первый трек — случайный из первых 10 плейлиста; анализ первого «пула» из 8 случайных
     треков идёт в фоне по 2.
  2. Пока играет трек, к пулу добавляются ещё (держим 8 проанализированных впереди). Следующим ставится
     лучший из пула по оценке §7.2 плюс «дуга энергии» вечера: первые ~20 минут энергия растёт, дальше держится
     высокой с редкими спадами (каждый 5–6-й трек — шаг вниз, чтобы не утомлять).
  3. Очередь в интерфейсе показывает уже выбранный следующий трек и «остальное — по ходу».
- Контекст очереди `party:<playlist id>`, заголовок «Вечеринка · <плейлист>»; Sonar Mix не трогается.
- Треки, которые не скачались или не проанализировались, идут в конец пула и играют с кроссфейдом.
- **Как сделано (Э6, сверено с кодом 2026-11-24).** Порядок и дуга — чистый `player/blend/party-core.ts`
  (`PartyOrder`, `arcTarget`, `trackEnergy` = громкость + темп в окне 85…170 BPM; тесты — `party-core.test.ts`),
  обвязка с плеером — `player/blend/party.svelte.ts` (`party.start / end / init`). Отличия от текста выше:
  - в «Далее» вечеринка ставит **по одному** следующему (`addToQueue(…, next)`, не автоплей), выбирая его
    в момент смены трека; если следующий ещё не посчитан, а в пуле досчитался лучший — меняет его, пока до
    конца текущего больше 40 с (дальше уже грузится поток B);
  - пул держит 8 «живых» треков (сбойные анализа не в счёт и добираются заново), а не 8 уже посчитанных;
    готовых нет — следующим идёт первый ещё считающийся (кроссфейд), сбойные — в самом конце;
  - трек, который пользователь поставил в «Далее» руками, играет первым, вечеринка ждёт его;
  - сведение включается само контекстом `party:` (`player.blendOn`), автоплей «похожих» на вечеринке выключен;
    тумблер сведения в плеере выключили — вечеринка кончается, очередь остаётся, контекст — снова плейлист;
  - значок — `vinyl` из MingCute (одна пластинка), своего «два диска» пока нет;
  - строка «остальное — по ходу» — отдельная строка `party` в `queue-view.ts` (без переключателя автоплея).

## 14. Тесты

Vitest, рядом с кодом. Синтетика генерируется в тестах (без файлов в репо):

| Что | Как проверяем |
|---|---|
| темп | щелчки 128 / 90 / 174 BPM ± шум → `bpm` ±0.5, не вдвое; щелчки с паузой в середине — тот же темп |
| сетка | щелчки со сдвигом 137 мс → `firstBeatMs` ±10 мс; темп 120 с ускорением до 126 → `gridStable = false` |
| такт | акцент на каждой 4-й доле (громче низ) → верный `downbeat` |
| фразы | 8 тактов тихо + 8 громко + 8 тихо → границы на 8 и 16, метки intro / drop / outro |
| тональность | аккорды до мажора (C–F–G–C) синусами → C major; ля минор → Am; шум → `keyConf` < 0.15 |
| громкость | синус −20 dBFS и −10 dBFS → разница 10 ± 0.5 |
| Camelot | таблица совместимостей, нужный сдвиг, учёт связанной скорости |
| планировщик | детерминирован; темп вне допуска → выбранный вид без синка, Авто — фильтр; нестабильная сетка → без синка; три длины дают разные такты при любом темпе; A не выходит за конец файла; обрезка не больше `cut`; топ-8 без дублей |
| кривые | у каждого вида: в начале B молчит, в конце A молчит; после свапа ровно один бас на 0 дБ; громкость с равной мощностью без провалов > 1.5 дБ; все резкие места ≥ 5 мс |
| контроллер | поддельные деки: пауза-продолжение, перемотка отменяет, «Следующий» завершает, ошибка B, промоут без `load()`, `current` = A до конца |
| вечеринка | порядок не повторяет треки, дуга энергии, непроанализированные — в конец |
| Rust | миграция 17, `blend_get/put`, `blend_source` берёт кэш, временный файл удаляется |

Ручная проверка перед пушем: 5 видов × 5 пар (электроника 124 → 126, рэп 90 → 140 (вдвое), поп в разной тональности,
спокойное → спокойное, трек без сетки — живой), пауза/перемотка/«Следующий» посреди перехода, вечеринка на плейлисте
из 30+ треков, нагрузка CPU в диспетчере — сведение не добавляет больше 3 % к обычному проигрыванию.

## 15. Готово, когда

1. Включил сведение, плейлист из электроники — переходы бит в бит, расхождение долей ≤ 20 мс по отладке, без щелчков.
2. Все 5 видов и Авто выбираются в кнопке и в настройках, работают и звучат по §8.
3. Пока A не доиграл — везде показывается A; потом B без перезагрузки и без паузы.
4. Нет анализа / ручное переключение / повтор одного / последний трек — ведёт себя по §6.1, без ошибок.
5. «Свести для вечеринки» играет плейлист сведением, энергия идёт дугой, треки не повторяются.
6. Тесты §14 зелёные, `npm run check`, `cargo test`; строки переведены на 5 языков.
7. Отладка видна только Dev; без Deep (когда пределы включатся) — замок с плашкой.
