# Аудит репо Sonar — 2026-11-21

Разбор всего монорепо глазами разработчика, которому завтра это поддерживать (навык `ponytail-audit`,
`.claude/skills/`). Только отчёт: код по нему не менялся. Пункты закрываем по номерам («сделай 1 и 3»), сделанное
отмечаем `✅ сделано YYYY-MM-DD` прямо у пункта.

**Что это за репо.** Свой музыкальный плеер: клиент для Windows (Tauri 2 — Rust + Svelte) и iPhone (SwiftUI)
играет треки SoundCloud, Яндекс Музыки, YouTube Music, VK и Spotify через аккаунты пользователя, со своими
лайками, смешанными плейлистами, волной и статистикой. Сервер (Python, бот `@SonarMusicApp`) пока крутится на ПК
владельца, сайт — Astro на GitHub Pages.

**Какую нагрузку считал.** Владелец и несколько друзей: один пользователь на устройство, один процесс клиента,
медиатека до тысяч треков; сервер — десятки пользователей, один процесс.

## Нужно исправить

### 1. Токен бота отчётов достаётся из exe
`windows/src-tauri/src/crashlog.rs:164-170`, `.github/workflows/windows.yml:44-46`

- **Что это.** Кнопка «Отправить лог» после сбоя шлёт журнал в Telegram ботом отчётов. Токен бота, чат и тему CI
  вшивает в exe при сборке (`option_env!`).
- **Проблема.** `Sonar-setup.exe` лежит в открытом релизе GitHub, и это не зависит от того, открыто ли само репо.
  Токен в бинарнике хранится открытой строкой: его вытаскивает `strings Sonar.exe | findstr ":AA"` за минуту.
  С токеном можно от имени бота писать в лог-группу, читать всё, что приходит боту (`getUpdates`), и удалять его
  сообщения.
- **Исправление.** Пока сервера нет: отдельный бот только для отчётов, без прав админа и без доступа к другим
  чатам, в отдельной группе, а не в общей лог-группе `-1002276939424`. С сервером — клиент шлёт лог на
  `POST /reports` API Sonar, токен бота живёт только в `.env` сервера, из CI и exe он уходит.
- **Если не делать.** Любой, кто скачал Sonar, может спамить в твою лог-группу или читать отчёты друзей
  (в журнале — названия треков, пути на диске).

## Стоит исправить

### 2. Кэш обложек на диске растёт без предела — ✅ сделано 2026-11-21
`windows/src-tauri/src/stream.rs:598-630` (`/cover`), `commands.rs:1245-1274`

- **Что это.** Локальный сервер `/cover` скачивает обложку с CDN и кладёт её на диск (`<кэш>/covers`), чтобы
  тема под обложку и коллажи брали её без сети.
- **Проблема.** Удаления нет: кэш чистится только кнопкой в «Хранилище». У кэша треков есть предел и
  вытеснение старых (`track_cache::evict_in`), у обложек нет. С 2026-11-21 коллажи сверяют обложки по картинке
  (`lib/cover-hash.ts`) и докачивают до 16 штук на карточку, так что кэш растёт быстрее.
- **Исправление.** При запуске и раз в час звать `track_cache::evict_in(cover_dir, 300 МБ)`, пропуская обложки
  локальных файлов (`sonarcover://…`, их читает `local::read_cover`, и пересоздать их без сканирования нельзя).
  Около 10 строк, отдельная настройка не нужна.
- **Как сделано.** `stream::prune_covers` — предел 300 МБ, при запуске (в фоне) и после каждых 200 новых
  обложек; открытая обложка «освежается» (вытесняются давно не открывавшиеся, а не давно скачанные); обложки
  локальных файлов не трогаются. Тест `prune_covers_keeps_local_and_fresh`.
- **Если не делать.** За месяцы поиска и Главной папка дорастает до гигабайтов, и пользователь узнаёт об этом из
  «Хранилища», а не от Sonar.

### 3. Тест значков сервисов падает на Windows-копии репо — ✅ сделано 2026-11-21
`windows/src/lib/service-icons.test.ts:31`, в корне нет `.gitattributes`

- **Что это.** Тест проверяет, что файлы значков в приложении — байт в байт копии из `brand/icon/`.
- **Проблема.** На ПК владельца `core.autocrlf=true`: git при выгрузке меняет переводы строк в одних SVG и не
  трогает другие, и 10 проверок падают. На CI (Linux) всё проходит, поэтому перед пушем на Windows `npm test`
  всегда красный, и настоящая поломка тонет среди этих 10.
- **Исправление.** Файл `.gitattributes` в корне со строкой `*.svg -text`: SVG хранятся и выгружаются как есть.
  Потом SVG выгрузить заново из коммита (не `git add --renormalize`: он записал бы в репо уже испорченные
  рабочие копии).
- **Как сделано.** `.gitattributes` с `*.svg -text`; на ПК владельца `npm test` — 890 из 890.
- **Если не делать.** К красным тестам привыкают и перестают их читать.

## Что проверено и в порядке

- **Пульт с iPhone** (`remote/`): команды принимаются только после `hello` или `pair`. Код привязки сгорает после
  нескольких неверных попыток, сравнение кода по постоянному времени (подбор по времени ответа не работает),
  ключи хранятся хэшем, ответ «не привязан» одинаковый для «нет такого» и «ключ не тот».
- **Локальный аудио-сервер** (`stream.rs`): `/seg` и `/cover` ходят только на разрешённые CDN (подсунуть чужой
  адрес и превратить Sonar в прокси нельзя). Локальные файлы требуют ключ сессии, их CORS открыт только окну Sonar.
- **Сервер:** пароли — argon2id, токены и коды — `secrets`, вход ограничен по попыткам на логин и на Telegram,
  логин без учёта регистра (`COLLATE NOCASE`), регистрация — в транзакции.
- **Запись в базу клиента:** добавление и перестановка в плейлистах — в транзакциях. В рабочем коде `store/` нет
  `unwrap()` (все — в тестах), поэтому 195 мест `db.lock().unwrap()` на практике не падают.
- **Интерфейс:** все `{@html}` — свои значки и флаги из сборки и QR пульта, чужого HTML (тексты Genius, названия
  треков) нет.

**Вывод:** в целом здоров. Первым — пункт 1 (токен бота в открытом exe), он единственный опасен уже сейчас.

**Что не проверял (не читал или не запускал):** iOS целиком (50 тыс. строк, только по названиям файлов);

## Нужно исправить

### 4. Заводской пароль админки совпадает с логином и лежит в открытом репо
`server/sonar/admin/auth.py:61-67`, `server/tests/test_admin.py:15`

- **Что это.** Пока админов нет, сервер сам заводит `folzy` с заводским паролем и требует сменить его при первом
  входе.
- **Проблема.** Пароль равен логину и записан открытым текстом в тесте публичного репо. Если сервер поднимется

- **Исправление.** Заводской пароль — случайный при первом запуске, печатается один раз в лог/консоль

- **Если не делать.** Чужой забирает админку в первую же минуту после деплоя.

### 5. CSP сайта блокировал встроенные скрипты — ✅ сделано 2026-11-22
`site/astro.config.mjs`, `site/src/layouts/Head.astro`, `site/src/pages/[...lang]/404.astro`

- **Что это.** Сайт отдаёт CSP (список, откуда браузеру можно брать скрипты) с хэшами скриптов.
- **Проблема.** Astro не хэширует `<script is:inline>`: класс `.js` на `<html>` и переадресация 404 на нужный
  язык не выполнялись — блоки не появлялись, FAQ не сворачивался, `/en/нет-такой` показывал русскую 404.
- **Как сделано.** Тексты обоих скриптов — в `site/src/lib/inline-scripts.mjs`, их хэши добавляет
  `astro.config.mjs` (`scriptDirective.hashes`). Тест `csp.test.ts` проходит по собранному `dist/` и требует хэш
  каждого встроенного скрипта в CSP страницы.
- **Если не делать.** Сайт выглядит сломанным у всех.

## Стоит исправить

### 6. Лимит входа копит записи на каждый новый логин и IP — ✅ сделано 2026-11-22
`server/sonar/accounts.py` `RateLimit.blocked`, `server/sonar/admin/auth.py` `AdminAuth.login`

### 7. Многошаговые записи админки без явной транзакции
`server/sonar/admin/users.py`, `server/sonar/db.py` (9 мест `with con:`)

- **Проблема.** База открыта с `isolation_level=None`, а при нём `with con:` в Python ничего не начинает:
  бан + выход со всех устройств + запись в журнал идут тремя отдельными записями. Сбой между ними оставит
  забаненного с живыми сессиями.
- **Исправление.** Помощник `tx(con)` в `db.py` (`BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`) вместо `with con:`.
- **Если не делать.** Редкие полу-сделанные действия, которые видно только по журналу.

### 8. Свой период в будущем давал «с завтра по сегодня» — ✅ сделано 2026-11-22
`server/sonar/admin/web.py` `_period`

- **Как сделано.** Конец обрезается до сегодня, начало — не позже конца. Тест `test_future_custom_period_and_huge_page`.

### 9. Перепроверка текста без времени держит открытие текста
`windows/src-tauri/src/commands.rs` `lyrics` (кэш → `fetch_track` в той же команде)

- **Проблема.** Раз в 3 дня у текста без времени команда сначала ходит на lrclib и лишь потом отдаёт старый
  текст: на медленной сети панель текста пустая несколько секунд, хотя ответ уже есть в кэше.
- **Исправление.** Отдать кэш сразу, перепроверку запустить фоном (`tauri::async_runtime::spawn`) и прислать
  событие, если нашёлся синхронный.
- **Если не делать.** Иногда текст «думает» без причины.

### 10. Огромный номер страницы ронял список — ✅ сделано 2026-11-22

- **Как сделано.** Номер страницы не больше `PAGE_MAX` (1 000 000): `OFFSET` больше int64 SQLite не принимает,
